# Issue #23386: bounded statement diagnostics
Revision 3, 2026-10-10. Owner: observability/frontend maintainers.
Tracking: [issue #23386](https://github.com/matrixorigin/matrixone/issues/23386); source baseline `888e1ea4469b6c2bf7a23c31f3376654cb8a30cc`. The implementing PR links this RFC.

## Gate, evidence and invariant
The persisted format, frontend/exporter/reader ownership boundaries, pre-release versus terminal lifecycle and SQL hot path require a design gate. No blocking design question remains. Performance, race, consumer and final independent review remain implementation delivery gates.
At this exact base, slow export builds all logical graphs, clones all physical operators/maps/background queries, then marshals. #29812 only replaces oversized encoded output afterwards. Normal export baseline supplied by root: 77–87ns/op, 288B/op, 2allocs/op. A 256-scope duplicate value-scan reproduction emits 52915 bytes / 256 repeated roots; slow export costs 415–422us/op, ~311KiB/op, 326allocs/op. Controlled traced SQL comparison (T=1s, compact enabled on head, 3 runs × 2s): SELECT base 163–165us versus compact 163–167us; prepared UPDATE base 1.07–1.35ms versus compact 0.85–1.25ms. Whole-process allocations and UPDATE timing are noisy; these runs do not prove all workloads unchanged.
Invariant: compact admitted output is useful, valid UTF-8 JSON, bounded before constructing a full graph/clone; normal successful L0 SQL retains the existing static bytes, allocation size classes, stats traversal and locks. #29812 remains the independent 65535-byte TEXT defense.
No new collection/counters, worker, cache, sampling, framework, root snapshot, billing algebra or live EXPLAIN PHY formatting. Details never become accounting totals.

## Owners and source facts

Models is the established ExplainData/PhyPlan owner, avoiding a persisted presentation format in generic statistic.

## Level policy and configuration
Encoded limits: **L0 no DTO; L1 2048 bytes; L2 8192 bytes; L3 49152 bytes**, including punctuation/omission metadata. Keep thresholds as fixed documented constants; one existing latency control T=`long-query-time` (default 1s), S=max(T,1s), saturating 4×S/16×S.
Choose the highest matched level; preserve all matched reason bits. Ordinary elapsed=max(wall-known waitActiveCost,0). Unknown wait-active is explicit; nil-handler fallback uses wall. Negative duration/wait is invalid/unavailable, never a huge uint. Producer wait and active time are not reduced by wait-active.

| Existing observation | L1 | L2 | L3 |
|---|---:|---:|---:|
| elapsed | > T | ≥4×S | ≥16×S |
| ExclusiveActiveNS | ≥1s | ≥4s | ≥16s |
| saturating sum of six producer waits | ≥1s | ≥4s | ≥16s |
| MaxDomainPeakLiveBytes | ≥64MiB | ≥256MiB | ≥1GiB |
| saturating S3 read+write bytes | ≥64MiB | ≥256MiB | ≥1GiB |
| SpillBytes | >0 | ≥16MiB | ≥256MiB |
| execution/terminal error incl. cancellation/timeout | — | any nonnil error | — |
| attempts | — | >1 | — |
| Quality | — | any nonzero | invariant failure/cross-pool free |
| existing standalone scheduling decision | true | — | — |

T=0 maps positive elapsed statements to cheap L1; L2/L3 latency floors remain 4s/16s. MO logger and composite child statements remain excluded from top-level diagnostics. Existing collection and tenant filters remain authoritative.
Add only `statement-diagnostics-format` = `compact-v1` (new default) or `legacy`; invalid values fail validation. Thread through existing observability/tracer config. It is an immutable deployment writer control, not another threshold framework.

## Two synchronous stages and minimal signatures
Before release: mark response time as today; select using current latency, existing preview, run error and existing scheduling standalone decision. Missing preview is unavailable. L0 does no new projection; L1 creates scalar DTO only; L2 captures selected logical rows; L3 captures selected physical outliers. Heavy helpers are called after admission so L0 gains no large stack frame/escape.
Preserve `RecordExecPlan(ctx, phyPlan)` interface/mocks. Add a private concrete record helper with `runErr error`; existing SQL execution defer calls it for TxnComputationWrapper after completeCompileExecution; non-concrete wrappers call existing interface. Public constructors can delegate nil error to private construction. Never retain the error/context.
At EndStatement, after Root.Seal, authoritative stats and final Status/Error, before Report, invoke one optional interface alongside ResourceSummarySetter:
```go
type StatementDiagnosticsSetter interface {
    SetStatementDiagnostics(ctx context.Context,
        summary resource.StatementResourceSummary, err error) (retain bool)
}
```
Compact setters select final=max(captured,terminal-selected), update scalar summary/outcome/phases and return retain=true for level≥1. Use existing DisableAgg before publication. Legacy serializers keep ResourceSummarySetter. No second mutex/root snapshot or recursive SetSerializableExecPlan under its mutex.
A terminal-only upgrade never rescans released plans. Emit final level and lower captured_level plus explicit details-unavailable reason. No terminal downgrade loses an earlier failure/partial resource fact. Terminal error wins outcome.
jsonPlanHandler implements the setter even for compound/scheduling-only handlers; absent marshalHandler is allocated only on positive terminal admission. If ExecPlan is nil, EndStatement installs a small scalar-only serializer using the same models policy/encoder after existing stats extraction, directly under current mutex. Its Stats contributes zero. Do not overwrite unrelated custom serializers. This closes parse/compile/early failures without a frontend callback or normal allocation.
Invalidate serializer/statement cached JSON upon terminal mutation; direct preterminal Marshal must not pin stale bytes. Return any previously handed-over buffer exactly once. Production still encodes once after completion. Free/pool reuse clears diagnostic references and aggregation flags.

## v1 schema and field semantics
Wire envelope is solely `{"statement_diagnostics":{...}}`. Add optional `StatementDiagnostics *StatementDiagnostics` tagged `statement_diagnostics,omitempty` to models.ExplainData for reader dispatch and selected container. Preserve normal handler field layouts: reuse existing marshalPlan pointer; no new pointer/embedded DTO on every handler. Compact Marshal emits only envelope, not other legacy ExplainData fields.
Required DTO fields: `version:1`, `level`, `captured_level`, numeric `reasons`, `outcome`, `summary`, `detail`. Optional `phases`, `scheduling`, `logical`, `physical` are absent when unavailable/unselected. No SQL, literals, UUID, Expr/column lists, full graph/edges, repeated unit labels, StatsInfo timestamps or duplicated error text.
Summary scalar fields: `wall_ns`, `elapsed_ns`, `wait_active_known`, optional `wait_active_ns`, `active_ns`, `wait_ns[6]`, `max_domain_peak_bytes`, optional `sum_domain_peak_bound_bytes`, `s3_read_bytes`, `s3_write_bytes`, optional `s3_requests[6]`, `egress_bytes`, `spill_bytes`, `attempts`, `retry_wall_ns`, `quality`, `missing_fragments`, `missing_memory_domains`. Optional zero counters may omit; present final summary is observed, not a fabricated preview. Omit allocator owner maps; do not Clone a whole resource summary.
active_ns=ExclusiveActiveNS, not host CPU. Memory names explicitly describe domain peak and sum-of-peaks bound. Wait order=lock/filesystem/IO-merger/remote/output/other; S3 order=head/get/put/list/delete/delete-multi. Unknown future quality/reason bits stay numeric. Integer units are in names; no NaN/Inf sanitizer is needed on compact DTO.
Stable reasons bits 0..9: elapsed, active, wait, memory, S3 bytes, spill, failure, retry, quality, scheduling. Outcome=success/failed/cancelled/timeout using typed MO codes and wrapped Go error identity, never text substrings. Optional numeric error code/fixed SQLSTATE; full messages stay in existing error column.
Optional phase scalars: parse_ns, plan_ns, compile_ns, prepare_ns, execute_ns from existing StatsInfo, only copied when admitted. These are diagnostic phase durations, not billing inputs or additive totals.
Logical row: `index` is query.Nodes array index matching physical NodeIdx; `kind` is enum; optional bounded `object` scan identity; optional first eight `children` plus children_total; `analyze_available`; scalar elapsed_ns=AnalyzeInfo.TimeConsumed (not exclusive CPU), wait_ns, input/output rows/bytes, memory_max_bytes, spill_bytes, read_bytes, s3_read_bytes. Allowed optional skew/min/max/disk counters may be included if useful. No timing arrays/protobuf clone. Nil AnalyzeInfo is explicit unavailable.
Physical row: deterministic scope/operator ordinal, remote bool, node=NodeIdx, bounded kind, scalar elapsed/wait/input/output/memory/spill/read/S3/network counters, optional call_count/quality. memory_bytes is producer-local, distinct from root domain peak. Link logical metadata by node index; no repeated table identity, Children, receivers, metrics/maps/background queries or process structs.
Scheduling scalar projection: attempt_count, exec_kind, reason, fallback, selected_count, dropped_count, failure_count, requested_pool/resolved_pool, truncated. Existing collection/standalone decision is reused. L3 worker/failure arrays are optional and may be omitted entirely in this fix. L1 may omit pools/other optional strings to meet header budget.
Detail: logical_total from known slice length; actual selected/encoded counts; physical_visited; captured availability (`complete`, `not_selected_before_release`, `no_query`, `no_physical_plan`, `compile_failed`, `bounded`); physical_truncated and limit reason; exact logical omitted count. After physical stop, never claim exact total or global topness. Candidate omission count must be named as such.

## Bounded selection and encoding
L1 never walks operators. L2/L3 scan logical nodes once only after admission. Keep top2 per six axes (elapsed/wait/memory/spill/IO/output rows)+first4 roots at L2; top4+first8 roots at L3. Deduplicate by index; union caps16/32; stable ties lower index. Candidate pointers exist only in synchronous helper; scalar/string copies happen only for retained rows.
L3 visits every child position plus local/remote/pre-scopes under depth64, ≤4096 operator/edge visits and ≤1024 scope visits. Charge attempted edges before dedup so alias/cycle input cannot defeat work cap. A bounded seen-operator set prevents expansion repeats. Deduplicate emitted candidates by stats pointer using the bounded candidate list; no second unbounded set. Top4 per same six axes plus quality/spill outliers, cap32; stable scope/visit ties. Negative producer diagnostics omitted/marked. Never recompute totals or AnalyzeInfo.
Strings: before copying scan only bounded prefix and count actual JSON escaped UTF-8 bytes, including controls/quote/invalid UTF-8 replacement. Max escaped object128 bytes; kind/reason/pool/category64 bytes. Disable HTML escaping consistently. strings.Clone bounded prefix avoids retaining giant backing strings. No formatting/cloning for rejected candidates.
Encoder: reserve2048 bytes for final header/metadata, then encode each bounded selected row to a ≤2KiB scratch buffer and append complete rows only when they fit. L2 uses remainder of8KiB for logical rows; L3 allows ≤16KiB logical and spends remainder of48KiB on physical. Highest-ranked rows precede root context. Emit final header with exact counts after row selection. Required scalar header fits2048 at MaxUint64; optional phases/scheduling strings are omitted by header budget, with omission metadata. Test worst header; ordinary overflow cannot discard useful summary.
Do not allocate/marshal a full tree/DTO then truncate/retry/replace it. Encoded JSON is never sliced. One output buffer has capacity≤64KiB; existing pool ownership is reused; discard larger buffers. Scratch/projection maps/arrays exist only after admission. Target peak additional L3 memory<512KiB, retained diagnostics<128KiB; normal allocation count and B/op exactly unchanged.

## Reader, rollout and lifetime closure
mo_explain_phy creates fresh ExplainData/result state per vector row and unmarshals once. Version1 dispatches to new formatter; absent diagnostics uses existing valid legacy ExplainPhyPlan golden output. Unknown version gives concise unsupported-version output. Malformed/empty/NULL/invalid format gives exactly one SQL NULL. Mixed rows cannot inherit previous data or append twice.
Normal shows outcome/reasons/summary/availability; verbose adds phases/scheduling/logical; analyze adds available physical. Modes never regenerate missing data. Live models.ExplainPhyPlan/EXPLAIN PHY formatting is unchanged.
Old readers ignore compact field and print empty; do not claim useful old-reader compatibility. During rolling upgrade explicitly configure each new writer `legacy`; upgrade every CN/SQL reader; activate compact-v1 through ordinary deployment. New installations/defaults get improvement immediately. Rollback switches writers legacy before reader downgrade; upgraded readers continue reading all history. No history migration; compact trees cannot be expanded losslessly.
Temporary legacy writer control retires once oldest supported reader understands v1, after next supported rolling-upgrade window; record release boundary in follow-up removal issue. Existing legacy EXPLAIN/CloneForExport helpers keep real consumers.
Unhappy closure: nil plan/preview/stats context; parse/compile errors; run errors/cancel/timeout; late terminal resource/phase trigger; missing fragments/AnalyzeInfo; synchronized prepared/retry generation; detached strings/stats after reset; bounded wide/deep/branch/alias/cycle; short diagnostic aggregation retention; L0 aggregation control; duplicate EndStatement; preterminal Marshal; Free/pool reuse. No retained live plan/context, double return/report or shadow accounting.

## Alternatives and accepted tradeoffs
Post-marshal cap and full-JSON→compressed-text still pay full graph/clone cost; chain following Children[0] loses branches. Capturing everything for every SQL to recover terminal-only details violates normal cost/lifetime. Selected bounded pre-release projection+sealed terminal scalar summary is the simplest closure; late details absence is explicit.
Level3 keeps logical bottleneck context and physical instance outliers; custom sparse maps/background queries stay absent to avoid recursive variable work. Full physical tree remains available through EXPLAIN PHY. No new tenant visibility, literals, distributed protocol, resource algebra or catalog column changes; bounded identities come only from current tenant plan.
Decision log resolved: models owner; existing L0 layout; fixed multivariate defaults; T0 cheap summary; two stages; current generation; optional terminal setter/nil fallback; late availability; bounded rows/strings; exact byte budgets; positive-level retention; default compact plus reader-first rolling control; temporary legacy retirement. Blocking questions: none. Implementation evidence remains root-owned.

## Implementation QA corrections
Prepared analysis keeps reusable topology, but Reset clears its previous-request resource summary. At capture after Run returns, a failed query without a current preview omits both logical and physical observations with `execution_failed_before_analysis`; initialized AnalyzeInfo and old operator counters are not current-generation proof. Failures after analysis retain their captured detail. Logger exclusion does not use the composite-child statistics flag. Error classification follows wrapped/joined typed errors. Export buffers larger than 64KiB are discarded. Real SQL tests synchronize on terminal publication because the wire ERR packet can arrive first.

## Performance acceptance
The new terminal admission hook costs approximately 25–35ns in the isolated nil/scalar-handler control, with unchanged allocation classes; this is the accepted cost of detecting resource/error triggers arriving after plan release. Ordinary exporter allocations remain 288B/op and 2allocs/op with overlapping timings. A-B-A traced SQL at T=1s shows no persistent SELECT/prepared UPDATE regression: compact SELECT 163–167us lies within baseline 161–173us; compact UPDATE 0.85–1.25ms overlaps baseline 1.06–2.02ms. This local evidence does not establish all workloads unchanged; process-wide UPDATE allocations/timings are noisy.
