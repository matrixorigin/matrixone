# Design v2: recover safe temporal secondary-index ranges

This document describes temporal range semantics and the requirements for extending
optimization coverage. The implemented first-stage access-path scope is defined by
[ordinary CBO integration](20261030-temporal-cbo.md). These
implementation decisions supersede the broader delivery goals below: parameter-bearing
queries, named timezones, automatic backfill, FORCE specialization and unsupported
predicate shapes retain the existing safe plan. Their optimization is future work;
semantic correctness, cancellation and fallback requirements still apply.

### Diagnostic-preserving admission

A candidate can suppress evaluation of other predicates even when its bound is pure. The row filter executes `FilterList` sequentially, and ordinary nested AND/OR evaluates their arguments; removing rows can therefore change row-scoped warnings, errors or side effects. This applies to both empty and nonempty candidates. Admission must positively prove the original semantic filter owners, including every expression evaluated between the physical scan and original residual, total and free of observable effects for skipped rows. Unknown functions and unproved paths reject the new candidate. The existing `areTruncationSafePredicates` is a useful positive structural proof, but parameter materialization and admitted execution-time clock expressions need separate proof. Do not treat its `ParamRef` case as sufficient: transport conversion may diagnose. Initially reject parameters without an execution-time diagnostic-free proof and a demonstrated safe-plan fallback on proof failure. A derived block hint or per-expression `filterScanStorageExprs` decision cannot supply the missing whole-owner proof, and must not bypass it at compilation or forwarding. An extension that enables parameter support must preserve parameter provenance and cover every affected scan and ancestor expression, including parameters already materialized to literals: a parameter outside the temporal bound can also diagnose. Capture all affected original expressions in `prepared_binding.go`, add per-execution diagnostic proof in `computation_wrapper.go` including its prepared cache-hit path, re-probe before each runtime plan/compile reuse, and rebuild with this candidate disabled when proof fails. A dedicated probe must evaluate the entire separately certified temporal bound with an isolated warning sink; the existing parameter-only collector/prober cannot discover outer NOW FSP errors because its statement-constant classification rejects real-time functions. Cancellation/OOM propagate instead of becoming SQL fallback. Until this complete path exists, reject candidates whenever any affected expression has parameter provenance, even if its bound itself is parameter-free; acceptance of that extension requires valid prepared bindings to regain eligible candidates and invalid/NULL/rebound executions to preserve the safe plan semantics. JOIN/AGG/WINDOW ancestors remain explicit optimization coverage limitations unless separately proven and implemented; benchmark reports must disclose these exclusions.

For the first implementation, restrict admission to candidates whose original semantic owner is the TABLE_SCAN. Inspect its complete original `FilterList` before rewriting, including filters later moved to a coordinator Restrict, and positively prove the scan's own `ProjectList`, `Limit` and `Offset` expressions safe as well. Check all predicates with a positive proof derived from `isTruncationSafePredicateExpr`, with a specifically certified mixed-temporal atom and bound; `CURRENT_TIMESTAMP`/NOW is admissible only via its reviewed statement-clock overload with omitted precision or a literal precision in 0..6, not merely `IsRuntimeConstant`. Invalid precision is diagnosed at execution, not necessarily at binding; parameterized precision is excluded unless the entire bound is separately probed for the current execution with an isolated warning sink, a proven safe-plan fallback, and re-probing on reuse. Cancellation and OOM propagate normally. For an index-only scan, retain all original predicates after column remapping and before sorting or LIMIT. For `JOIN INDEX` backfill, preserve all original base-scan predicates and admit only the known internal PK equality join without additional unproved intervening operators. If the residual owner or intervening path cannot be established, reject this candidate, including under FORCE, using the existing safe access path. The existing fulltext order proof is insufficient. Before access-path selection, build parent links from the query roots, propagate an explicit admission result to the scan, and inspect every affected ancestor path; reject shared or multiple-parent paths unless every path is proven. First admit only PROJECT, FILTER and SORT with all evaluated expressions positively proven total and effect-free, and pagination only with proven safe LIMIT/OFFSET expressions and an ordering proof. Reject unknown operators, JOIN, AGG, WINDOW, SET and DML ancestors; the internal PK equality INDEX join generated by the rewrite is the sole join exception. Preserve existing ordering and LIMIT correctness proofs separately; if the planner cannot carry or reconstruct the proof through rewrites, disable the candidate. An upper Restrict beyond an exact original residual does not see rows rejected by that residual, but its ordering and LIMIT behavior still need this check.

Tests must compare rows, warning counts and error codes against the existing safe plan for normal and reversed sequential filters, nested OR, empty and nonempty candidates, no matches and matches, invalid casts, arithmetic diagnostics, volatile calls, unknown functions, LIMIT, covering/backfill/FORCE, memory/flush and prepared valid→invalid→NULL→valid reuse. They must also prove the ordinary clock-bound selective case remains eligible. The exact coverage and backfill plan shapes and provenance of this proof must be independently reviewed before candidate generation. Independent design review approved this admission contract; candidate integration must implement and verify it.

The reader must not interpret arbitrary folded false booleans as empty: unrelated existing queries have not passed this admission gate. Carry a default-false `TemporalCandidateGuard` on the original `plan.Expr`: only the scan admission gate may mark the exact internal notEmpty guard or a boolean AND/OR subtree composed solely of such guards. `ReplaceFoldExpr` explicitly copies that bit into `FoldVal`; preserve it through protobuf, deep copies, execution reset and remote re-folding. Never mark an arbitrary expression merely because it contains a helper; only a validated boolean guard with that provenance may trigger the new reader empty path. Default/missing provenance remains unknown. Internal function ID or `ContainsTemporalBound` alone is not admission proof; only the original scan gate may attach the provenance. Add regression tests for unrelated folded-false expressions as well as admitted guard forwarding and reset.

For initial implementation, disable the new candidate for the entire prepared query when the original query has parameters or absence of parameter provenance cannot be proven. A materialized literal does not always preserve `Literal.Src`; absence of a visible `ParamRef` is not such a proof. Pass the conservative fact from the pre-binding owner to the builder. Parameterized queries only become eligible after the required execution-proof/replan closure above is complete. `DeepCopyExpr` manually copies both carrier fields; generated protobuf cloning alone is insufficient. Place each marked guard as a child of a row-dependent candidate expression or explicitly implement root folding, because `ReplaceFoldExpr` returns a constant root without constructing a `FoldVal`.

The reader may produce a valid Empty only for a marked `FoldVal` that is constant, has boolean type, and contains the complete valid false encoding. True is non-narrowing; NULL or masked-out results, missing provenance, wrong type, malformed/incomplete encoding and nonconstant folds remain unknown/ALL.

The same restriction applies to more selective OR object pruning and upper-aware range seek: their old behavior can retain a block with unknown metadata where a newly optimized object check skips it, thereby suppressing diagnostics. The admission gate marks the complete derived candidate filter with a separate `TemporalCandidateFilter` provenance bit; preserve it through deep-copy and RPC. Reader compilation passes that bit down only inside that marked filter. Missing provenance retains the old OR and seek behavior, even if a nested expression mentions a helper. The guard bit and filter bit serve different purposes and are never inferred from function names alone.

## Goal and established behavior

PR #31624 prevents the observed wrong results by declining unproved serialized DATETIME/TIMESTAMP lookups. On the public reproduction, automatic `d < now(3)` scans the base table; FORCE can scan and decode the whole index without a useful encoded block filter. An already safe earlier composite equality prefix can still prune. No comparative performance number has yet been established. The goal is to recover selective index/object/block pruning for both column directions and the common predicate shapes without changing SQL results, existing encoded data, or requiring an index rebuild.

The invariant is **SQL TRUE implies that the physical candidate contains the row**. A candidate can over-fetch. The original bound SQL predicate remains a residual evaluated on the same logical row, before LIMIT/OFFSET/top-N and before any consumer that assumes one physical key per equality. `NULL` and SQL UNKNOWN never count as TRUE. This is a candidate design, not a cast of a SQL bound into the key type. `compareDatetimeAndTimestamp` (`pkg/sql/plan/function/func_compare.go`) converts DATETIME with the execution's zone and then calls `Timestamp.TruncateToScale` at the TIMESTAMP operand's scale. Despite its name, that method rounds nonnegative values when the next digit is >=5; signed division truncates toward zero, and the `-1` zero sentinel is returned unchanged. For scale 3 and an ordinary positive value, a `.123` result includes `.122500` through `.123499`; a `.123500` value rounds to `.124`.

`Datetime.convertToGoTime` is not just Go `time.Date`: if the normalized result lies in a detected forward-transition gap, `nonexistentLocalTimeBoundary` chooses the first valid second after the transition and keeps the original microseconds. In a gap, successive local seconds can map to the same absolute second; do not assume linearity within a local interval. In a fold Go may select one of two offsets. Both `ZeroDatetime` and `ZeroTimestamp` are `-1`, and valid early-year DATETIMEs can convert to other negative timestamps. The safe implementation cannot assume modern positive dates, an invertible cast, or that a single boundary's offset applies to an unbounded range. See also the Go [`time.Date` and `Time.ZoneBounds` contract](https://pkg.go.dev/time@go1.27.1) and [TZif RFC 9636](https://www.rfc-editor.org/rfc/rfc9636); MatrixOne's gap behavior above is the controlling implementation, not a new SQL-standard interpretation.

## Selection: bounded conservative range with local refinement

Use one shared, execution-local candidate builder in new `pkg/container/types/temporal_index_bounds.go`; it depends only on temporal types, `time` and `context`, not on the SQL planner or readers. Its concrete internal contract is:

```go
// Full and Empty are disjoint. Full is the non-NULL physical domain.
type TemporalCandidate struct {
    Lo, Hi int64 // inclusive raw physical component values
    Sentinel int64 // -1 if needed; otherwise Lo, a duplicate point
    Full bool
    Empty bool // SQL TRUE is proven impossible, never a calculation failure
}
func BuildTemporalCandidate(ctx context.Context, keyKind T, timestampScale int32,
    bound int64, boundIsNull bool, op TemporalOp, zone *time.Location) (TemporalCandidate, error)
```

`TemporalOp` is an internal small enum for the canonical atomic `=`, `<`, `<=`, `>`, `>=`; SQL-function binding supplies the actual timestamp scale and operand orientation. This is temporal-only, not a general range framework. The builder represents one atom over the physical component, not serialized bytes. `Full` returns `[math.MinInt64,math.MaxInt64]` for the non-NULL temporal key and is never empty. A NULL bound is `Empty`, because the admitted eager-safe atomic comparison cannot be SQL TRUE; the positive equality case below provides another exact `Empty`. Unknown/unsupported, malformed or overflow always means `Full`, never `Empty`. The extra point covers the zero sentinel if the original atom matches it, otherwise duplicates `Lo`. This avoids a scan of a distant zero-value block when the sentinel cannot match. Every caller also retains the original SQL residual. Cancellation propagates `ctx.Err`; optional calculation/representation failure widens to the physical full range, not a new SQL error. The residual preserves original SQL errors and diagnostics only when the whole-owner diagnostic admission proof above holds. `Full` is safe for an atom because its SQL TRUE requires the temporal key to be non-NULL; it is not an ALL arm for an arbitrary OR that can be true on NULL.

### TIMESTAMP key, DATETIME bound

At execution, for a non-NULL bound whose evaluation is proven statement-stable and diagnostic-free, compute `K = bound.ToTimestamp(zone).TruncateToScale(key.Scale)` using the same code and execution location as the scalar comparator. Compare the physical TIMESTAMP key to `K` with the canonical original operator; for an encoded multi-part key use the closed/prefix range rules below. The candidate is exact for the temporal comparison in this direction, but still retain the SQL residual and existing NULL/prefix checks. `K` may be negative or `-1`; never substitute a parsed timestamp, local display string, or a cast with different SQL mode. Checked conversion/arithmetic and a valid scale are mandatory; if input falls outside the proven conversion domain, use ALL.

### DATETIME key, TIMESTAMP bound

All arithmetic below is signed integer microseconds in MatrixOne's year-1 epoch, with checked/saturating operations. For scale `s`, let `q=10^(6-s)` for `0<=s<=6`; let `F(D)=D.ToTimestamp(zone)` and `R_s(t)=t.TruncateToScale(s)`. For every supported, non-overflowing `t`, including negative values and sentinel `-1`, `abs(R_s(t)-t) < q` (and is zero for scale 6). This is a deliberately conservative alternative to a complex exact inverse near `-1`. Given TIMESTAMP bound `B`, any nonzero SQL match satisfies:

| SQL predicate after orientation to `D op B` | Necessary UTC condition | Safe closed DATETIME condition when `e_min <= D-F(D) <= e_max` |
|---|---|---|
| `=` | `B-q <= F(D) <= B+q` | `[B-q+e_min, B+q+e_max]` |
| `<` or `<=` | `F(D) <= B+q` | `D <= B+q+e_max` |
| `>` or `>=` | `F(D) >= B-q` | `D >= B-q+e_min` |

This table widens open endpoints; exact strictness is restored by the original residual. For scale 6 use expansion zero. The extra width is bounded by two precision units plus the offset envelope, not by days or decades in normal operation. `D == ZeroDatetime` is handled separately: evaluate the sentinel comparison `R_s(ZeroTimestamp) op B`; union the `-1` point if it can be TRUE. Do not include a sentinel point by stretching a modern equality range down to `-1`. A nonzero `D` whose conversion happens to equal the timestamp sentinel is still covered by the same inequality: `R_s(-1)=-1` has zero rounding error. Check `B±q`, offset scaling, serialization and extrema for overflow; any unsupported/invalid type, invalid precision, arithmetic overflow or malformed representation produces ALL. Do not silently use `TimestampMinValue` as a hard validity bound (`ParseTimestampWithContext` explicitly does not enforce it). Use existing Packer typed ordering; do not alter any bytes.

The wall-time proof itself covers `D in [0,Dmax]`, where `Dmax=DatetimeFromClock(9999,12,31,23,59,59,999999)`. Do not assume every physically stored DATETIME belongs to that interval: `timestampToDatetime` and `datetimeToDatetime` append conversions/scale rounding without checking the resulting calendar year, and DATETIME preinsert validation checks zero, not the full year. A source-level boundary to exercise is a valid `9999-12-31 23:59:59.999999` TIMESTAMP written in UTC, then converted to DATETIME after switching the session to `+14:00`; another is rounding a typed DATETIME(6) at the 9999 limit to DATETIME(0). These SQL paths are proposed tests, not a claim they have already run. To make the candidate safe even before storage-domain assumptions, put **two constant physical tails once around the whole selected temporal candidate group**: `D in [MinInt64,-2] OR D in [Dmax+1,MaxInt64]`. Apply the same proven equality prefix to both, and OR them with the main range and conditional `-1` point in the *same* scan. The original residual determines their result; the normal empty-tail case should be eliminated by zone maps without extra block reads. If the reader cannot represent these disjoint branches without widening to a useless hull, it must decline pruning; this is an explicit reader/benchmark gate.

For the common positive-date case, use the exact **raw timestamp** bucket before adding the offset envelope. When `s<6`, `q>=10`, `h=q/2`, and `B>q`, let `floor=floor(B/q)*q` and `ceil=ceil(B/q)*q` with checked integer arithmetic:

| `R_s(F(D)) op B` | Necessary raw timestamp interval |
|---|---|
| `=` and `B%q==0` | `[B-h, B+h-1]` |
| `=` and `B%q!=0` | no TRUE is possible; return `Empty` plus residual |
| `<` | `F(D) <= ceil-h-1` |
| `<=` | `F(D) <= floor+h-1` |
| `>` | `F(D) >= floor+h` |
| `>=` | `F(D) >= ceil-h` |

For nonnegative `t`, this is the existing half-up rule, including the precise microsecond immediately before a half-unit. For negative `t`, Go signed division makes `R_s(t)<=0`: it cannot satisfy equality or a lower-bound comparison with `B>q`, and is already on the included side of an upper-bound comparison. The `-1` sentinel has the same ordering property. Thus the table is safe for *all* source rows, not an assumption that source timestamps are positive. Translate a raw lower/upper endpoint to DATETIME using `e_min`/`e_max` and handle sentinel separately as above. For `s=6`, use the exact bound and checked `-1`/`+1` microsecond for strict inequalities. Near zero, for negative bounds, or if the positive condition cannot be proved, retain the conservative `q` table. This common-domain precision avoids a dense boundary's extra bucket while avoiding a complicated full-domain negative/sentinel inverse framework.

#### Proving and tightening `e_min/e_max`

1. For a proven fixed-offset zone, use the *actual* session offset `O` for nonzero DATETIME values, not its name. Frontend `updateTimeZone` accepts `-14h < offset <= +14h`; these offsets are exact seconds. To prove single-offset behavior using only public `ZoneBounds`, first require both epoch bounds to be zero; then let `Z=time.Time{}` and inspect `Z-1µs` and `Z`, each `.In(loc)`. Verify each period contains its probe; require the former's start and the latter's end to be `IsZero`, and require their offsets to equal each other and the epoch offset. The former start cannot be the real year-1 `Z` because it precedes that probe, and the latter end cannot be `Z` because a right end must follow its probe; they therefore signify -infinity and +infinity. TZif/POSIX transitions are integral seconds, so the two probes cover any real transition at Z with no other transition in between. Otherwise take the general path. Checked arithmetic applies to internally supplied `time.FixedZone` offsets too.
2. For Go locations made by the supported public APIs, use an initial **representation bound**, not an invented DST bound: Go 1.27.1 `time/zoneinfo_read.go` reads each TZif offset as `int32`; `tzsetOffset` accepts at most 168h plus minutes/seconds and its default daylight adjustment is still within int32. `time.Location` transition fields are private; public `FixedZone` is the exception allowing an arbitrary `int`, and its unique offset is visible at the epoch. If that epoch offset exceeds the signed-int32 bound, or the location was populated through an unproved/unsafe path, return ALL rather than using this bound. Otherwise all chosen offsets are in `[-2^31,2^31-1]` seconds. This covers ordinary `LoadLocation`, `LoadLocationFromTZData`, Go's `Local`, UTC and bounded `FixedZone`; the implementation and test must establish the public-constructor premise against the actual toolchain. `time.Date` in this Go version performs a lookup at the wall label interpreted as UTC, then may perform a second lookup at that label minus the first offset. Include both lookup results.
3. The gap correction checks transitions within 48h of the Go candidate and at most 16 transitions. When it succeeds and the gap transition wall labels are proven inside years 1–9999 as specified below, its effective offset `D-F(D)` lies between the before/after transition offsets, with a conservative extra one second for the code's inclusive `beforeWall = transition - 1 microsecond` and preserved fraction. When it does not succeed, Go's chosen offset from step 2 covers the fallback. Seed with `M=(2^31+72*3600+2) seconds`, in checked microseconds. This covers the maximum lookup offset and the scalar gap detector’s complete transition lookback even when its out-of-calendar wall labels make the effective offset differ from both transition offsets; it is not a claim about the largest real DST jump.
4. First form the necessary raw UTC interval `[L,U]` from the exact positive table or the conservative near-zero table; an absent side is infinite. Do not scan transitions for years 1–9999 for a one-sided predicate. With initial `M`, an equality starts from finite wall band `[L-M,U+M]`. An upper-only predicate has uncertainty strip `[U-M,U+M]` and includes the entire lower tail; a lower-only predicate has strip `[L-M,L+M]` and includes the entire upper tail. Intersect each strip with the proven DATETIME domain. For each wall band `W`, enumerate all periods for `I0=W` interpreted as UTC; let `O0` be their offset interval. Enumerate `I1=W-O0`, and let `O1` be its offset interval. The Go candidate time is in `C=W-(O0 union O1)`; enumerate `I2=[C.min−72h−1µs,C.max+48h]` including transition-adjacent periods, following the UTC year and negative-Unix midnight rules in the implementation discovery below. Ordinary possible offsets are `O0 union O1`. An explicitly enumerated transition in `I2` contributes its before/after offsets with the one-second allowance **only if `W` intersects that transition's actual forward-gap wall interval**. For a fully covered fine pass, without that intersection no gap correction can have been chosen; the coarse negative-Unix pass also includes its POSIX uncertainty envelope; in particular do not unconditionally add ±1 second to an ordinary millisecond equality window. If a period cannot be fully covered, `ZoneBounds` does not advance outside the proved leap-year case, a time representation overflows, a location cannot be proved, or the transition budget is exceeded, keep the prior proven wider band or return ALL; never use a partial extrema set.
5. Intersect the previous candidate with `[L+e_min,U+e_max]`, retaining the entire definitely-included tail for one-sided predicates. The next ambiguity strip is `[L+e_min,U+e_max]` for equality, `[U+e_min,U+e_max]` for an upper-only bound, and `[L+e_min,L+e_max]` for a lower-only bound, each intersected with the preceding strip: the other tail is now definitely included. Repeat at most **two** times. The exact raw `L`/`U` remain fixed through refinement; do not replace them with `B±q` after calculating a precise bucket. This admits ordinary current New York/London equality as a precision-scale interval away from a transition instead of the union of all historic offsets. Near a gap/fold the envelope may be wider, which is safe. A scan must enumerate its initial period and advance at the applicable `ZoneBounds`, UTC year, or negative-Unix midnight boundary, taking care that Go's zero `time.Time` can represent either an unbounded edge or the real year-1 instant: when ambiguous inspect immediately before/after or decline narrowing. Do not probe only a guessed 24h/48h band before establishing the `M` envelope.

Cap each helper evaluation at **4,096 zone periods**, with at most two refinements and a cancellation check at least every 64 periods. Admit at most **8 atomic arms per temporal OR/IN** and **64 temporal atoms per whole query** in the initial implementation; each atom adds at most its main range plus one sentinel point, with two physical-domain tails shared by the group: at most 18 disjuncts. AND combines these safely without distributing into an exponentially larger DNF. Several endpoint helpers and filter copies may independently traverse the same periods; the budget is **per evaluation**, not an unimplemented statement-wide budget, and scope replication can add further evaluations. The 10M/100M benchmark must measure total compile/fold cost. Fixed zones are O(1). No cache shared across statements, no background worker, no unbounded allocations. If an arm cap or a representation limit is exceeded, retain the existing safe plan/prefix.

## Actual predicate semantics and shapes

- `=`, `<`, `<=`, `>`, `>=`: canonicalize operand orientation on a copy and apply the corresponding candidate above. Never alter the executable ID of the original residual.
- `AND`: intersect proven supersets; an unproved conjunct contributes ALL and stays a residual. An impossible intersection can be empty only after preserving the original diagnostic contract. Separate scalar range bounds retain their own TIMESTAMP scales.
- `OR` and mixed `IN`: OR together atomic candidate expressions, not separate scans, so rows are not duplicated. Admit an OR only if **every** arm has a proven candidate and SQL TRUE in every arm implies that this indexed temporal component is non-NULL; otherwise retain the existing safe plan, or a separately safe AND prefix. In particular the non-NULL typed full range cannot represent an unsupported `d IS NULL` arm. `base_binder.go:8115` can lower heterogeneous IN to a balanced OR of comparisons; analyze the **bound plan**, not an assumed SQL-text expansion. A homogeneous `IN`/folded vector is handled by its actual operator/type contract and existing same-domain fast path; it is not automatically equivalent to mixed scalar equality. NULL list members never contribute TRUE but remain in the original expression.
- `BETWEEN`: follow `operator_between.go:opBetweenDatetimeTimestamp`, not a blind rewrite to two independently rebound operators. In particular when DATETIME value and *both* TIMESTAMP bounds are present, both comparisons use the **lower bound's timestamp scale**; when only one endpoint is TIMESTAMP, use that endpoint's scale. TIMESTAMP value with DATETIME bound converts the bound at the value's scale. Preserve the original BETWEEN residual. Existing `IN_RANGE` is a different bound operator whose public flag is a uint8 literal (`base_binder.go:5850`); do not infer scalar-pair precision without proving its actual bound overload.
- Composite regular index: retain an exact safe equality prefix followed by at most one temporal range component. Encode each endpoint as `serial(prefix..., typed temporal bound)` and use existing `prefix_between`/`prefix_in_range` closed envelopes where suffixes exist; full tuple/direct typed key uses its proper non-prefix operator. An unbounded side under an existing prefix uses the established prefix endpoint semantics; for no prefix use an explicitly verified physical-domain extreme, or ALL if it cannot be represented. Require the existing index completeness proof, including `hintedIndexContainsQualifyingRows` for nullable UNIQUE suffixes. The original mixed predicate is rechecked on `serial_extract` for covering scans or on the base row for backfill. Prior byte-string prefix/NULL exactness residuals remain in addition to temporal residuals.
- FORCE INDEX obeys the same semantic proof; its existing decoded full-index fallback remains available. `indexPartFixedByEquality`, `canPushRegularIndexOrderedLimit`, and cursor rewriting must not treat a DATETIME precision bucket as a single physical value. A direct TIMESTAMP key equality is mathematically one key, but the initial implementation still retains the residual and does not push a LIMIT through it.
- `NOT`, `!=`, `NOT IN` and `NOT BETWEEN`: do not complement a superset; that can discard true matches. Retain the current safe plan, or an independently safe AND prefix, unless a separate existing exactness proof applies. This work does not weaken existing CHAR, decimal, string or other non-temporal guards.

## Planner-to-reader integration and timezone identity

**Decision: internal execution-time bound functions in existing fold expressions.** The planner may sample a safe current bound for *costing*, but must not publish that sample as a reusable executable endpoint. Register internal-only overload families in `pkg/sql/plan/function/function_id.go` and `list_builtIn.go`, with implementation in new `pkg/sql/plan/function/temporal_index_bounds.go`: one maps TIMESTAMP-bound to DATETIME-key endpoints and the other DATETIME-bound to TIMESTAMP-key endpoints, plus a boolean `notEmpty` selector. Arguments are the original typed, row-independent bound expression, canonical operator, TIMESTAMP scale, endpoint selector (`Lo`, `Hi`, `Sentinel`) and compile-set narrowing permission. Endpoint result OID and scale are the actual key component type; the helper is *not STRICT* and returns non-NULL endpoints even for a NULL argument. Although the current `serial` propagates NULL, the guard is still necessary to suppress the shared physical tails; `serial_full` has different NULL behavior and must not be substituted. A separate always-non-NULL `notEmpty` result is false exactly when `Empty` is proved; it returns true on failure/unknown. Compute this guard in O(1) from NULL/alignment, without walking timezone transitions. These are real same-version registered function IDs which may appear in a remote raw expression; no serialized bound-value marker or physical-plan side channel is needed; the explicit guard/filter admission-provenance bits described above are required.

For each DATETIME-key atom the planner emits one normal encoded closed range plus one OR-ed encoded point for the `Sentinel` selector, guarded by its `notEmpty`. The point is -1 exactly if the zero-sentinel original comparison can be TRUE, otherwise it is `Lo`, already in the normal range. TIMESTAMP-key atoms need only the normal range; all atoms retain their original scalar residual. Combine atomic candidates and their `notEmpty` guards with the same AND/OR structure; put the two shared physical tails outside the group under its combined guard. Thus `OR` of an empty arm and a nonempty arm retains the latter, while a NULL-bound single predicate or entirely empty OR performs no scan. With a leading exact prefix, construct the endpoints as `serial(prefix..., helper(...))` and use `prefix_between` plus `prefix_eq` for a suffix-bearing key. For a full key use the appropriate full-key range/equality operators. `Packer.EncodeDatetime` and `EncodeTimestamp` use ordered signed `encodeInt`, so typed `math.MinInt64`/`math.MaxInt64` cover the non-NULL physical component, including legacy raw values; prove this at the real reader boundary before relying on it. On optional bound-construction failure both endpoints become the physical full range and the sentinel point duplicates its low endpoint; no plan swap or SQL NULL endpoint is required. The separate point and tails are part of a single scan's filter expression, not a second scan or UNION. The planner only selects an index when its pre-existing completeness proof covers all SQL-TRUE rows even if this function widens to the full non-NULL component domain, including nullable UNIQUE suffixes. Unsupported OR arms decline the entire candidate before this choice.

The helper is statement-context-dependent, and so are all parent expressions containing it. Extend both folding owners, `pkg/sql/plan/utils.go:ConstantFold` and `pkg/sql/plan/rule/constant_fold.go`, plus the semantic predicate in `pkg/sql/plan/function/function.go`, so neither the helper nor a containing `serial(...)` or other ancestor can be materialized by planning, prepare-time or speculative constant-folding, regardless of `varAndParamIsConst`; merely setting `realTimeRelated` is insufficient for all fold modes. It must still be admitted as a row-independent runtime fold and by `ExprIsZonemappable`, and must not be marked volatile, because `filterScanStorageExprs` rejects volatile expressions. Add a bounded, temporal-lookup-only recursive admission proof in `index_comparison.go`: literals are safe, while parameterized bounds are excluded unless the entire bound has a diagnostic-free proof for the current execution and a safe fallback; function overloads qualify only when their semantic owner declares them statement-stable, pure and total/diagnostic-free for the supplied operand types, recursively with safe arguments. Reuse existing diagnostic checks but do not assume `IsRuntimeConstant` by itself proves no error or warning. NOW and equivalent clock overloads naturally qualify under that contract, not by matching SQL text or patching NOW. Lazy/volatile, warning-producing, potentially erroring or unproved overloads decline the optimization. This proof is required because the executor evaluates a function argument before invoking the helper; the helper cannot catch an error from an eagerly evaluated unsafe argument.

Only the original-scan admission gate may create secondary, block or compound temporal candidates. If a later rewrite adds or moves an unproved semantic owner or loses the proof, remove the hint and fall back. `appendTemporalStorageHints` may forward an admitted hint but must not independently grant admission. ## Implementation discovery: Go 1.27 timezone boundaries

The original ZoneBounds traversal is amended after source inspection and counterexamples. Go's POSIX extension can return a non-advancing end on the last UTC day of a leap year, and its negative-Unix-second arithmetic can change the selected rule at midnight and again one second later without an advancing ZoneBounds boundary. POSIX transition rules can also cross a UTC year boundary. A coarse pass must visit TZif periods while including a signed 612000-second POSIX envelope for any negative-Unix window; the fine pass additionally splits negative-Unix intervals at UTC midnight and the following second. Both passes split at UTC year boundaries and share the original 4096-period budget. For nonnegative Unix seconds only, an end at UTC day 366 of a leap year that fails to advance is the POSIX post-rule branch; its offset remains constant to the next UTC year. Other non-advancing bounds fail open. Gap transition inspection starts 72 hours and one microsecond before the earliest candidate, covering the scalar gap detector's stale-bound lookback, and extends 48 hours after the latest candidate. If its coarse inspection window includes any negative Unix second, include the POSIX envelope even when the two lookup windows themselves do not.

`DatetimeFromClock` maps out-of-calendar wall labels differently from UTC plus the offset. Before narrowing a named zone, the entire gap inspection window expanded by the maximum signed TZif offset, including the microsecond before a transition, must be inside years 1–9999. Otherwise return Full. An apparently disjoint initial seed also returns Full until the calendar proof has been established. This conservatively gives up named-zone pruning near the calendar ends; proven fixed offsets remain eligible. A synthetic TZif with a year-0 forward transition followed by a year-1 transition reproduces the scalar's non-obvious mapping and is a mandatory regression. These changes require renewed Terra/max design review and an independent Astra/xhigh challenge before implementation review.

## Error, lifetime, cost and compatibility

Each executing scope owns its own helper and temporary ranges for one execution. Plan selection must admit only runtime constants whose value is statement-stable and whose optional extra evaluation cannot emit diagnostics or introduce an earlier error; use existing statement-diagnostic/purity proofs (`constant_filter_diagnostic.go`, `function.IsRuntimeConstant`) for generic functions. Preserve parameter NULL and statement error semantics. Check cancellation while traversing zone periods and do not convert cancellation into a successful full scan.

No persisted key/collation/catalog change or rebuild. A new binary must read existing index data. This branch supports shutdown-only upgrades, so do not introduce MORPC feature gates, old-peer fallback, or downgrade claims; see `.agents/skills/mo-dev/references/upgrade-compatibility.md`.
