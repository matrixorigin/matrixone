# Retire unconsumed mocks and helper closures

Version 2, 2026-10-24. Owner: engineering-quality issue #29249.
Implementation: [PR #31011](https://github.com/matrixorigin/matrixone/pull/31011).
Frozen base: `2b94111625d746d048468ccc214c6b27fc23bd0d`.

## Boundary and alternatives

The first batch removes disabled comment implementations. This extension retires
unused mock families and disconnected internal helper declarations. It introduces
no replacement execution, validation, storage, lifecycle or state mechanism.
Retaining the unused paths preserves maintenance obligations. Moving them into
other files or adding compatibility wrappers would preserve the same obligations.
Select complete removal after repository-wide reference and ownership checks.

Mock inventory resolves import paths and aliases, rather than equating identically
named mocks in different packages. Keep every consumed interface and its complete
method/recorder surface. Regenerate selected public interfaces with pinned
mockgen v1.6.0 reflection mode; root Make owns native prerequisites and flags.
Consolidate the duplicate auto-increment mock into the existing frontend helper
and migrate its one consumer. Keep planner mocks with handwritten defaults and
trace mocks whose generic signatures cannot be regenerated by the pinned tool.

The helper scope comprises unused error-construction convenience wrappers,
retained-expression byte-count helpers, PtrLen generic conveniences, abandoned
storage/catalog constructors and adapters, test-data builders, option wrappers,
and unconsumed named interfaces. Keep live constructors, the error registry and
codes, codecs, storage layouts, query admission/accounting and configuration
fields. Retiring an unused setter does not alter the actual defaults or readers.
Parser constructors, protocol revision predicates, diagnostic tools, tagged
entrypoints and optional external capabilities are excluded from this retirement.
Unknown out-of-tree imports of these internal Go helpers are outside the source
compatibility proof; SQL, SDK, service and persisted contracts remain unchanged.

## Proof and validation

Treat lexical and AST inventories as candidate discovery only. For each selected
declaration, follow imports, function-value references, interface implementations,
registration/global initialization, generated callers, all checked-in build tags,
tests and documentation. Self-recursive helper closures require proving absence
of external incoming arcs. Remove complete dead closures and unused imports;
retain shared dependencies. No instantiated object, wait or resource owner may
be removed through a name-count heuristic.

Compare regenerated retained mock methods after local parameter/import alias
normalization. Review type aliases and equivalent variadic append separately.
Preserve live-path tests, assertions and fixtures. Retire the isolated
`TestEngineColumnInfo` getter self-test together with its disconnected
`ColumnInfo` / `engineColumnInfo` declarations and compile-time assertion.
Its two assertions exercise only the retired member getters; it has no SQL or
protocol oracle to migrate. Existing MysqlColumn/protocol result-metadata tests
remain unchanged. Other removed test helpers have no caller. No new runtime, race, persistence or performance claims are
introduced. Native/compiler and incremental vet/configured lint validate the
changed package and consumer closure. Tests are not executed under this task's
current instructions; record that limitation explicitly.

## Design review decision

Separate in-session design review, before helper implementation, with the getter-self-test closure reviewed
before its own edit: **GO** for the
bounded retirement above. The size gate is met by non-generated source deletion;
no major subsystem boundary is restructured. The critical invariants are zero
incoming live references, unchanged live ownership/ABI/formats, preserved mock
behavior, and unchanged active test oracles. Discovery candidates outside this
boundary remain excluded. This decision admits implementation; final source and
static-evidence review remain required before delivery.
