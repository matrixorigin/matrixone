# Key-owned execution for INTERSECT and EXCEPT

Issue: [#32069](https://github.com/matrixorigin/matrixone/issues/32069). Implementation branch: `codex/issue-32069-setop-perf`. Design base: `89ca3dbbf6d594d7614b8e1ca80f6b0300ed3cd2`.

## Problem and decision

The four binary membership set operators merge both input streams into one membership owner for the default configuration. The scans can be parallel while hash build and probe remain serial. On one private CN with four CPUs, 1,000,000 and 100,000 distinct, non-null BIGINT rows, and the default spill settings, three warmed runs at the design base took 25.0–25.4 ms for INTERSECT ALL and 28.4–28.9 ms for EXCEPT ALL; equivalent semi/anti controls for this particular input took 4.1–6.0 ms. Swapping INTERSECT ALL inputs took 63.9–64.0 ms. Results were counted; these timings are not a general equivalence proof for SQL bags.

The existing DISTINCT-only local keyed exchange helps when a sufficiently large `agg_spill_mem` is explicitly set; it does not cover ALL or the default setting. On the same 1M/100k input and three warmed runs, default INTERSECT took 24.6–26.7 ms and EXCEPT 64.9–69.0 ms; the explicit 1 GiB setting reduced them to 11.4–13.0 ms and 22.4–28.0 ms, while swapped INTERSECT remained 61.0–62.4 ms. The existing exchange uses one feeder per input, and this evidence does not prove that direct multi-producer routing will improve the ALL workload. ALL deliberately uses one owner today: broadcasting inputs to multiple counting operators multiplies results. The change extends the existing keyed membership execution instead. Both inputs are partitioned by an equality-preserving key, and each partition has one existing membership operator. No new set-op state machine or persistent, client, plan, or remote pipeline format is introduced.

## Semantic contract

For each complete physical equality class `k`, every occurrence from either input reaches exactly one owner. INTERSECT ALL returns `min(left(k), right(k))` left occurrences, EXCEPT ALL returns `max(left(k)-right(k), 0)` left occurrences, and the DISTINCT variants return the applicable class at most once. NULL participates in set equality. The operator must return values from the left input, including their visible representation: physical keys may normalize PAD SPACE, collation or other domains independently of output values.

Each router hashes the same proven subset of the physical equality tuple. Equality of the full tuple implies equality of that subset; a router hash collision can put different classes together but must never split equal classes. The existing kernel still evaluates the complete physical key and uses its current hash-state membership representation. That representation does not compare original keys on a hash-state collision; this pre-existing limitation is not changed into exact collision resolution here. Routing may separate unequal keys whose full-key hash states collide. Never route on raw text when physical equality normalizes it. The first eligible form is the existing identity-column subset with the same physical and visible type and a demonstrated equality-compatible hash. Unsupported or unproven key domains use the existing single-owner execution. A composite key may use a safe subset even when another component has a computed normalization.

Do not replace ALL with a semi/anti join: duplicates require count arithmetic and `NOT IN` has different NULL semantics. Do not exchange INTERSECT inputs solely to reduce build size: physical equality need not imply identical left and right visible representations. This design retains the existing right build and left output.

## Scope graph and ownership

The compiler chooses the route before changing child scopes. A coordinator-local source may route directly only when its actual execution path clones the scan/load pipeline for every declared worker, its root has no ordered-Top or other gather obligation that wrapping would hide, and it is not shared, terminal-dispatch or otherwise unsupported. A source with `Mcpu > 1` alone is not proof of cloning: the default `ParallelRun` path can run it once. Otherwise the existing plan is retained. A remote input first reaches a coordinator-local merge through the existing remote transport and is routed outside the serialized subtree; its local wrapper contributes one router. If more than eight routers would be created, consolidate complete input scopes through the existing per-side local merges; never discard a source or count fewer actual workers. Consolidation limits routers, not owners: each router can send to every admitted owner.

The owners run on the coordinator only while it is an admitted, schedulable query worker and its runtime state is not explicitly draining or drained. Otherwise use the existing stage placement, including a remote single owner when required. Their outputs are concatenated once before existing global sort, offset and limit handling. Remote scans remain parallel, but set CPU and memory remain on the coordinator and remote bytes still cross the network.

Each set owner has one receiver per source scope: left inputs use `[0,L)` and right inputs use `[L,L+R)`, with one partial merge per range. Every receiver's terminal count is the actual clone count for that source, or one for a non-cloned coordinator wrapper; independent sources must never overwrite each other's count on a shared receiver. Feeders are attached once to the owner-stage scope tree. Runtime clones copy routing metadata and participate in the statement allocation lifecycle. The local-only router must never enter a serialized remote subtree. Scope shapes for which coordinator placement, producer completion, or ownership cannot be established retain the existing plan.

Keep left and right feeders independent: an owner building from the right must not depend on a left feeder that is blocked by backpressure. Existing merge, dispatch, connector, shuffle and membership operators own their existing transitions. A result owner uses the ordinary kernel and full key; neither whole input nor whole hash table is broadcast to every owner. Plan construction errors must release partial state and return the original error rather than panic.

## Admission and capacity

Automatic selection is independent of `agg_spill_mem` and `join_spill_mem`; zero means their existing automatic behavior, not unlimited memory. Choose the parallel path only for non-TP, sufficiently large estimated work, more than one usable producer and coordinator CPU, a known safe key, and a supported scope/demand shape. Use estimates only for profitability, never as a correctness or memory bound. Consider both input streams when estimating parallel work: set-node DOP currently derives from left-side block estimates and can hide a parallel right side. Cap the stage at eight owners and eight routing producers, and respect `max_dop` and coordinator CPU. A starting work threshold is 250,000 estimated input rows; invalid or unknown estimates retain serial execution.

Exchange and transport each copy the selected row. On the measured workload, that cost overtook parallel membership gains for wide strings. Restrict automatic routing to an estimated row width of at most 72 bytes. Follow scan statistics through direct, non-repeating column projections; when that lineage is not proved, use the existing conservative declared materialized-row estimate. Unknown or wider rows keep the existing execution. This is a profitability heuristic, not a semantic limit; stale statistics can still produce either choice.

Before routing, use a read-only generation method that takes the existing budget mutex once and observes both query cap/use and CN cap/use; checked subtraction gives the smaller remaining headroom. A live CN ceiling below already admitted usage means zero headroom, not an invalid budget. This creates no reservation or second controller. For `S` actual local routing clones plus one for each coordinator remote-input wrapper, a finite positive row-size estimate `W` at least as large as the declared materialized row and the observed scan estimate, `U = 8 MiB + 2*S*8192*W`, and available query/CN headroom `H`, first choose the largest owner count `P` in [2,4] with `2*P*U <= H`, additionally capped as above. Raise `P` from four to eight only when the CPU, `max_dop` and actual input-worker limits each allow eight and `U <= H/16`; otherwise preserve the first choice, including two or three when appropriate. There is no intermediate five-to-seven-owner case. All arithmetic and float-to-integer conversions must be checked; unavailable, invalid, zero or overflowing estimates choose serial. This is a profitability and blast-radius heuristic, not an allocation reservation. Bound or reject unsafe scope fanout rather than silently multiplying producers.

The new router's hash and selection scratch, split batch storage, queue/spool copies and owned fixed metadata must be charged to the same live statement/CN account as the set kernels. A synchronous owned-output Shuffle policy participates in the statement allocation lifecycle only when selected; its non-owned mode does not activate or alter accounting for ordinary shuffles. Runtime clones copy the policy and bind through the existing runtime-owner attachment.

BatchSet/pool uses an optional immutable effective destination selection for its generation. The same selection governs ready-credit prediction, partial-tail append/seal decisions, `Union` and the full-row `Extend` path, shared-lane selection and recycle-buffer compatibility. Nil retains today's source-provenance behavior. Never relabel an allocated vector or mutate a borrowed input selection; compare batch and vector provenance, including capacity class. A one-bucket result is copied into an accounted output unless the complete input batch and every vector have compatible active provenance and its lifetime can safely be retained by the spool; when copying, set the bucket on the output.

The clone duplication context currently constructs a shared pool before runtime clones bind allocation owners. For owned-output routing, create a shared lazy pool descriptor during duplication and reserve/initialize its bounded metadata once in `Prepare` after account binding. Failed initialization publishes its original error to all clones. Pool cleanup releases its batch payloads, while the shared metadata reservation remains live until transport borrowers have drained and the account owner is retired; it is then released exactly once. Each clone owns and frees its own scratch. Retain `sels` headers as views into one accounted int32 backing with bounded per-bucket count/prefix metadata, and use an allocation-selected off-heap hash vector. Pending views and the input stay alive across a blocked write. Charge non-MPool headers and pool/spool metadata using the existing transient-memory reservation, sized for the input column count, and MPool payload through its allocation account without double charging.

Live admission is authoritative for every allocation, including replacement-growth peaks. A stale headroom estimate cannot bypass it. Insufficient headroom before execution chooses serial. After consuming input, capacity or other failure returns the original failure and cleans up; it does not replay the operation or silently switch owners. Shared-pool and per-clone metadata use the same guarded transient-admission protocol: sample providers without the pool lock, then acquire the pool lock before the budget lock for the final decision. At a definitive rejection, freeze whether the clone context has stopped while the budget remains locked; after releasing the budget lock, resolve and publish the pool's existing first error while still holding the pool lock. Release the pool lock before resolving a frozen context cause. Earlier pool failures and stops win over a later rejection, and a later stop cannot replace an already recorded rejection. Sender cleanup and scope completion use that same pool outcome, while query-level cancellation retains its existing priority. The resolver cannot call a provider, clean up, or reacquire the pool lock; cleanup and release already follow pool-before-budget lock order. This protocol adds no independent resource owner and does not guard ordinary MPool allocations. A parallel query can therefore fail under a tight or concurrently consumed budget where a serial query might have completed, and eight owners can fail where four might have completed; it must fail within the existing budget, without partial durable effects or leaks. The operators do not gain spill support.

## Control, compatibility and lifecycle

Preserve caller context and deadline through every feeder, receiver and remote merge. Existing terminal ownership remains: normal producers finish through their current Reset protocol; failed/cancelled producers abort bounded queues and wake waiters. If a runtime clone is retired before acquiring a pool holder, abort the shared exchange so other clones do not wait for its impossible terminal event. On startup, evaluation, registration, allocation, dispatch, downstream stop or cancellation, cancel sibling work, join started scopes, release never-started scopes, preserve the first substantive error and drain transport borrowers before clearing allocation selections and the resource generation. Reset/reuse cannot retain a previous generation's map, counters, scratch, or owned batches.

The compiler does not currently propagate ancestor demand to a set node. Before selecting the route, prove that both complete arms and physical-key expressions are total and side-effect free, regardless of ancestor demand. Reuse the expression and predicate proof behind `setMembershipInputIsTotal`, with whole-plan ownership counting, and adapt its structural checks to the remapped physical plan: `remapAllColRefs` clears binding tags, so the pre-remap helper cannot be called unchanged. Validate remapped column references against their actual inputs and reject shared, recursive and unsupported nodes. This permits ordinary scan/project/count plans while avoiding new evaluation of a volatile or erroring row after an ancestor stops. Branch-local LIMIT/ORDER BY and other unsupported demand shapes retain the existing route. Reusable prepared TP pipelines retain their existing route; an AP execution may qualify only after specialization and fresh compilation, without caching stale key or topology decisions. Recursive/shared source or nested exchange shapes require an ownership proof or use the existing route. These conditions are execution-contract guards, not protocol-version fallbacks.

No catalog, storage, client or inter-CN wire change is made. Existing remote participants see the same input and result formats. New operators and account-owned memory are confined to the coordinator-local stage; mixed binaries do not receive the local routing metadata. There is no upgrade migration or new user setting.

## Cost and alternatives

Expected work remains O(L+R) for membership, plus one routing hash and bounded batch redistribution for each row. State is O(distinct right keys) for ALL and INTERSECT; EXCEPT DISTINCT may retain O(distinct left or right keys). Exchange buffers add bounded producer/owner batches and can increase peak memory and copying. Skew can concentrate one equality class on one owner. At 16 DOP on one host, increasing the owner cap from four to eight reduced issue-scale 10M/1M count-query medians by approximately 29–33%; a 4M/1M four-key input slowed from 58.87 to 64.77 ms in the measured runs. Those measurements do not promise a win on every distribution. Small and low-headroom queries avoid the exchange.

Alternatives considered:

1. Keep one owner and only optimize the membership hash. A controlled no-NULL BIGINT primitive benchmark measured existing StringHashMap at 23.3–23.9 ms versus IntHashMap at 4.1–4.2 ms for 100,000 inserts and 1,000,000 probes. This is not a SQL benchmark and the maps do not have proven identical NULL or collision behavior. It does not establish a safe substitution.
2. Rewrite to joins and aggregates. Correct bag expansion, NULL equality and preservation of left representatives require additional state and work; ordinary semi/anti joins are not equivalent.
3. Broadcast to multiple existing kernels. This multiplies ALL results and duplicate work; the previous single-owner correctness fix explicitly rejected it.
4. Partition by proven equality and reuse membership kernels. This adds exchange work but preserves one owner per class and allows parallel set work without another count state machine. Correctness and measurable benefit are required before delivery.
5. Propagate a distinct-key estimate solely to choose four or eight owners. Current compiled set keys do not carry a reliable input distribution, an output NDV does not establish row balance, and rewriting that metadata can affect existing expression comparisons. Do not introduce planner state or an unvalidated cutoff for this fanout decision.

## Validation and acceptance

- Public SQL: all four operators, asymmetric duplicates, NULLs, empty sides, multiple batches, normalized text and mixed casts; compare complete result bags and left-visible bytes. Cover a safe identity subset plus another normalized key, and confirm fallback for unproven keys. Test nested sets, branch and ancestor LIMIT/ORDER BY, prepared specialization/reuse and type changes. Extend existing fixtures where they already cover the same semantic cell.
- Typed compile topology: one destination per equality key, independent left/right input registers, source-specific terminal counts, four/eight DOP and headroom boundaries, coordinator placement and serial fallback. Check no local routing state enters remote serialization. Existing single-owner tests remain relevant for ineligible shapes.
- Allocation/lifecycle: account selection and destination provenance, retained and direct batches, queue saturation, skew, low budgets and allocation rejection at scratch/split/spool, partial startup, first error versus cancellation, early consumer stop, reset/reuse and zero terminal account usage. Exercise real pipeline entry points with deterministic barriers; run owning packages and changed regressions under `-race`.
- Topology: execute a two-CN SQL witness with real remote scan work and coordinator-local owners, plus empty input, cancellation and remote failure. Verify no sender or receiver remains blocked after termination.
- Performance: repeat the existing warmed 1M/100k SQL harness on the same host, `GOMAXPROCS=4`, `max_dop=4`, default spill settings and identical data. The physical plan must select 2–4 owners. Median INTERSECT ALL, EXCEPT ALL and swapped INTERSECT ALL should each improve by at least 20% from their baseline; report dispersion and machine load. At 16 DOP, compare four and eight owners on the 10M/1M input and both input orders, including a run without explicit ANALYZE; target at least a 20% median reduction on the measured ALL cases. Recheck DISTINCT with default and explicit settings. Measure small, wide, low-NDV, high-NDV hot-key and low-memory controls, query/CN peak memory and cancellation cost; investigate repeatable regressions over 15% or 3 ms, whichever is larger. No benchmark threshold can override correctness or budget failures.
- Run incremental format/vet/configured lint for the affected closure and normal plus required race tests. A pending CI run is not a pass. Preserve the baseline fingerprint and invalidate only evidence affected by later changes.

A routing or capacity invariant that cannot be proved, a missed default-workload performance target, or incomplete cancellation/accounting evidence blocks delivery rather than silently introducing an opt-in or intermediate solution.
