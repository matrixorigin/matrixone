# Issue #32814: physical SET index backfill

Design author: `gpt-6.1-terra`, `max`, independent session `/root/enum_design_review`; 2026-11-16. Scope: 4.2-dev and main supported nonunique indexes containing SET, alone or with ENUM. This supplements the approved ENUM index design and narrows its previous “do not change SET” requirement: allow a physical SET reference **only in authenticated generated backfill**, leaving public SET/serial semantics untouched. No implementation or release is approved here. The exact versioned revision needs an independent design review before production implementation.

## Evidence and contract

Both candidate branches reproduce selected-index read errors and unsuccessful mutations for an existing-row `INDEX(e,s)` where e is ENUM and s SET (`enum-set-index.sql`, `42-enum-set-index.out/.err`, `main-enum-set-index.out/.err`). In 4.2, `42-enum-set-hidden.out` shows old rows store SET display as string-tagged `46...`, while later DML/inline rows store the bitmap as unsigned-integer-tagged `40...`. A pure SET index also fails its actual Index Table Scan on 4.2 (`42-enum-set-prefix-controls.out/.err`). Exact released-baseline attribution remains separate.

`isSetPlanType` represents SET as `T_uint64` plus a nonempty `Enumvalues` member payload. The normal binder yields its display text, while DML index maintenance uses the stored UINT64. That conversion is non-injective: `SET('', 'a')` can display bitmap 0 and bitmap 1 as the same empty string.

For each supported build, hidden keys and PK payloads for existing rows must match ordinary DML for the same source snapshot. A whole-column SET component carries its exact unsigned bitmap, including zero, high bits and NULL; never derive it from display text. ENUM remains its own typed ordinal/domain. For a supported transformed/prefix part, use exactly the current DML transformation and physical input; this task does not define new SET/ENUM prefix semantics. Preserve strict/IGNORE, warnings, public expression behavior and storage format.

## Design

1. Generalize the existing statement-local ENUM-index descriptor/marker into an equivalent physical-special-type backfill capability. Activate it when a needed key or PK reference is ENUM **or recognized SET**, covering pure SET and mixed indexes. Recognize SET only by the existing `T_uint64 && Enumvalues != empty` discriminator; never mark arbitrary UINT64 or infer from names. A preexisting `SET('')` whose empty payload is indistinguishable from UINT64 follows the existing UINT64 physical path; do not manufacture metadata or claim to repair its general type semantics.
2. Retain the approved owner/executor trust boundary: derive exact expected statement from the owning validated index and source schema, escape identifiers, parse exactly one statement, independently validate its full relevant generated AST, then verify tenant, relation IDs, current schema, needed key/PK physical types and sequence numbers in the owning transaction. Mark only the proven direct ENUM/SET AST references needed for that statement. No user SQL, arbitrary internal executor, session switch, broad binder flag, name match, nested expression or public function can enable it.
3. Bind marked SET references to the source's typed UINT64 vector without the display wrapper. Preserve the member payload at plan boundaries where a later typed SET consumer needs it; serialize the bitmap via the existing UINT64 encoder. Do not reinterpret as ENUM, varchar, float or signed value, narrow it, parse labels or remove bits. Existing corruption/invalid metadata must continue through the applicable existing validation rather than be silently normalized. NULL remains NULL. The binder and remote plan retain existing feature/protocol gates.
4. Preserve current admissibility: SET cannot be a newly authored UNIQUE or primary-key part on either branch; do not accidentally admit it through the new descriptor or UNIQUE precheck. Existing ENUM UNIQUE prechecks remain keyed identically to their writer. MASTER's indexed parts are VARCHAR and its PK cannot be SET, so do not broaden MASTER admission. Pure SET and mixed SET secondary keys use the same DML serializer, not an alternative format.
5. For any actually permitted prefix SET key, apply the generated prefix operation to the same typed input as DML and prove full stored bytes match inline DML. Do not change general substring semantics. If a supported form cannot be proven, reject that build before publication. ENUM-prefix compatibility and legacy replay are a separately reviewed decision, not an implicit consequence of SET marking.
6. Discard statement-owned marks on success/error/cancel/retry and clear them for nested statements or session reuse. Preserve parent identity, access checks, transaction/deadline, existing locks, CCPR semantics, error categories, and atomic schema/index publication. A source/target/domain mismatch fails before effects. No automatic on-disk rewrite or unreviewed capability is introduced.
7. Confirm `serial_extract` reads a SET UINT64 bitmap and a typed consumer that needs SET identity receives the original `Enumvalues`. Only add targeted SET result-domain propagation if a reachable typed consumer needs it; do not change the general UINT64 domain. Validate actual chosen index reads against scans for non-injective display values; if a newly selected optimization cannot preserve semantics, fall back safely.

Marking and schema checks are bounded by key/PK metadata and statement size; no per-row membership reparse, extra scan, new cache/worker, wire field or durable format is introduced. Reuse the existing descriptor and DML serializers.

## Existing data and release

Previously populated indexes with display-encoded or mixed SET entries are not automatically repaired. Before release determine affected supported-catalog scope and a safe documented drop/rebuild from base rows using fixed code, then verify hidden entries and follow-up mutations. A rebuild failure must preserve base rows and report an error. The existing stopped-cluster fence, 4.2→main new-ENUM bridge hold and catalog/recovery gates continue independently.

## Required proof

- Typed/unit/negative tests in both branches: pure SET and mixed index statements mark exactly the permitted special-type AST references; UINT64, unrelated SET, user serial/expressions, nested/session reuse and unrelated internal statements remain unchanged. Verify legal quoted names, wrong account/source/target/domain/shape and actual schema drift fail closed, with cleanup after cancellation/retry. Preserve ENUM domain/encoding checks.
- Real SQL: compare inline-created index with rows-before-ADD for pure SET and both ENUM/SET key orders. Assert complete hidden key/payload byte sets and counts before/after INSERT, UPDATE, DELETE and reinsert, including the reproduced failures; compare actual selected-index versus scan results. Cover bitmap 0 and bitmap 1 with `SET('', 'a')`, NULL, multiple members and high-bit boundary, plus strict/IGNORE as supported. Assert both intended affected rows and data, not only no errors.
- Cover same-domain typed consumers/`serial_extract`, visible and numeric output, ordering and non-injective display without silently collapsing bitmaps. Include permitted SET-prefix controls against inline DML; compare exact baselines and MySQL separately before making prefix compatibility claims. Confirm SET UNIQUE/PK rejection and ordinary UINT64, VARCHAR and ENUM-only controls.
- Exercise temp tables and two simultaneously alive sessions, a non-system tenant, failure after partial work, cancellation/retry, restart and rebuild of an actually affected test index. Verify source rows, catalog and hidden index on failure. Preserve protocol-floor and remote-plan checks. Run affected owner race/static and independent final review on exact committed content.

This is a proposed design only; the versioned design gate, implementation, migration policy and final validation remain open. No product worktree file was modified.
