# Issue #32814: physical SET index backfill

Design author: `gpt-6.1-terra`, `max`, independent session `/root/enum_design_review`; 2026-11-16. Scope: 4.2-dev and main supported nonunique indexes containing SET, alone or with ENUM. This supplements the approved ENUM index design and narrows its previous “do not change SET” requirement: allow a physical SET reference **only in verified generated backfill owned by a trusted in-process caller**, leaving public SET/serial semantics untouched. No implementation or release is approved here. The exact versioned revision needs an independent design review before production implementation.

## Evidence and contract

Both candidate branches reproduce selected-index read errors and unsuccessful mutations for an existing-row `INDEX(e,s)` where e is ENUM and s SET (`enum-set-index.sql`, `42-enum-set-index.out/.err`, `main-enum-set-index.out/.err`). In 4.2, `42-enum-set-hidden.out` shows old rows store SET display as string-tagged `46...`, while later DML/inline rows store the bitmap as unsigned-integer-tagged `40...`. A pure SET index also fails its actual Index Table Scan on 4.2 (`42-enum-set-prefix-controls.out/.err`). In 4.2, an inline `SET('','a','xyz')` prefix index encodes bitmap 0/1/2/3/4 as string prefixes 0/1/2/3/4; the old ADD path instead used display prefixes and an UPDATE missed a row (`42-set-prefix-discovery.*`). Exact released-baseline attribution remains separate.

`isSetPlanType` represents SET as `T_uint64` plus a nonempty `Enumvalues` member payload. The normal binder yields its display text, while DML index maintenance uses the stored UINT64. That conversion is non-injective: `SET('', 'a')` can display bitmap 0 and bitmap 1 as the same empty string.

For each supported build, hidden keys and PK payloads for existing rows must match ordinary DML for the same source snapshot. A whole-column SET component carries its exact unsigned bitmap, including zero, high bits and NULL; never derive it from display text. ENUM remains its own typed ordinal/domain. For a supported transformed/prefix part, use exactly the current DML transformation and physical input; this task does not define new SET/ENUM prefix semantics. Preserve strict/IGNORE, warnings, public expression behavior and storage format.

## Design

1. Generalize the existing statement-local ENUM-index descriptor/marker into an equivalent physical-special-type backfill capability. Activate it when a needed key or PK reference is ENUM **or recognized SET**, covering pure SET and mixed indexes. Recognize SET only by the existing `T_uint64 && Enumvalues != empty` discriminator; never mark arbitrary UINT64 or infer from names. On 4.2, `SET('')` has empty payload and is indistinguishable from UINT64; retain that existing path and do not manufacture metadata. Current main encodes its single empty member with a reserved nonempty payload (`types.EncodeSetValues`) and must preserve `SET('')`, including bitmap 0/1. Historical payloads actually empty remain indistinguishable; never infer a lost domain.
2. Treat all same-process Go callers that can construct the exported executor spec/option or call `plan.WithEnumIndexBackfill` as part of the trusted computing base; these APIs are not an unforgeable DDL-owner capability. Audit their actual call sites. The owning DDL caller derives the expected statement independently from the validated index/source schema, escapes identifiers, parses exactly one statement and verifies the full relevant AST, tenant, relation IDs, current schema, needed key/PK physical types and sequence numbers in its transaction. These checks catch mismatches and accidental misuse; self-supplied SQL, account and IDs do **not** authenticate against a malicious same-process caller. A SQL client cannot directly supply this Go option; no cross-tenant exploit is asserted. A generic executor with no explicit option, user SQL, session switch, broad binder flag, name match, nested execution and public function do not themselves acquire marks. Mark only proven ENUM/SET occurrences in the validated statement and retain the ordinary DDL privilege/tenant checks. If untrusted in-process callers are in scope, introduce and independently review an actually non-forgeable owner capability instead of claiming these comparisons provide one.
3. Bind marked SET references to the source's typed UINT64 vector without the display wrapper. Preserve member payload at plan boundaries where a later typed SET consumer needs it. For a whole-column component, serialize its bitmap via the existing UINT64 encoder (tag 0x40). Do not reinterpret the raw reference or whole component as ENUM, varchar, float or signed value, narrow it, parse labels or remove bits. A prefix is a distinct transformed component: run the existing DML substring conversion on the physical reference; its string result uses tag 0x46, as specified in item 5. Existing corruption/invalid metadata must continue through the applicable existing validation rather than be silently normalized. NULL remains NULL. The binder and remote plan retain existing feature/protocol gates.
4. Preserve current admissibility: a recognized SET (`T_uint64` with nonempty member payload) cannot be a newly authored UNIQUE or primary-key part on either branch; do not accidentally admit it through the new descriptor or UNIQUE precheck. 4.2's empty-payload `SET('')` is indistinguishable from UINT64 and accepts UNIQUE/PK; main's reserved nonempty encoding identifies `SET('')` and rejects UNIQUE/PK (`42-set-singleton-admission.*`, `main-set-singleton-admission.*`). Preserve each branch's behavior. Never reconstruct a domain from an actually empty historical payload. Existing ENUM UNIQUE prechecks remain keyed identically to their writer. MASTER indexed parts are VARCHAR, and this work does not broaden its existing PK admission. Pure SET and mixed SET secondary keys use the same DML serializer, not an alternative format.
5. For a permitted SET-prefix key, apply the existing generated prefix operation to the physical bitmap, as inline DML does, and prove full stored bytes match inline DML. The existing 4.2 example therefore changes ADD from display-prefix keys to bitmap-derived string-prefix keys; disclose this targeted correction and its old-index rebuild boundary. Do not change public `substring` semantics. If a supported form cannot be proven, reject that build before publication. ENUM-prefix compatibility and legacy replay are a separately reviewed decision, not an implicit consequence of SET marking.
6. Discard statement-owned marks on success/error/cancel/retry and clear them for nested statements or session reuse. Preserve parent identity, access checks, transaction/deadline, existing locks, CCPR semantics, error categories, and atomic schema/index publication. A source/target/domain mismatch fails before effects. No automatic on-disk rewrite or unreviewed capability is introduced.
7. `apply_indices.go` can replace a SET key by `MakeSerialExtractExpr`, while the binder currently restores member metadata only for ENUM, dropping SET `Enumvalues` from its UINT64 result. Make the `serial_extract` result retain the exact validated source SET domain from its target-type argument when, and only when, that target is recognized as SET; leave ordinary UINT64 metadata and runtime UINT64 bitmap unchanged. Cover all actual `apply_indices` callers, not just one helper, and do not copy unproved domains or blindly overwrite derived nullability/type details. If the exact source domain cannot be proved, disable that specific index-only rewrite or fail closed rather than guessing. A plan-level exact-domain test and an actually selected composite-index scan must check bitmaps 0/1, NULL and typed consumers against a table scan. Preservation of public same-domain `INSERT SELECT` is a separate existing-assignment question: a table scan collapses 1 to 0 and 3 to 2 for `SET('','a','xyz')` on the candidate (`42-set-consumer-discovery.out`) and independently on the official 4.2.8 release (`release428-set-consumer-repro.out/.err`), so index metadata alone must not be presented as fixing this pre-existing behavior. General 4.2 SET assignment is tracked separately in #30771; a broad assignment fix is outside this scoped index repair. The current main candidate preserves 0/1/2/3/4/NULL for both scan and chosen index (`main-set-consumer-discovery.out/.err`); main must continue to preserve them, while 4.2 must match the official release baseline rather than be silently regressed.

Marking and schema checks are bounded by key/PK metadata and statement size; no per-row membership reparse, extra scan, new cache/worker, wire field or durable format is introduced. Reuse the existing descriptor and DML serializers.

## Existing data and release

Previously populated indexes with display-encoded or mixed SET entries are not automatically repaired. Before release, inventory conservatively by tenant and catalog: indexes involving a recognized SET key (including prefix/mixed forms) on existing tables may include faulty builds; absent reliable build-origin metadata, do not infer safety merely because a CREATE-style index could have been correct. Include restored catalog/snapshot cases and disclose that an actually empty payload cannot be distinguished from UINT64 by this mechanism. Publish an operator procedure that quarantines affected indexed access and writes during inspection/remediation, verifies the base table is authoritative, and rebuilds from its rows with corrected code. The rebuild SELECT must be proven by its chosen physical plan to read the base relation/authoritative storage, not an old secondary index containing suspect keys; if that cannot be guaranteed, fail the rebuild before publishing an index rather than trusting source relation ID. Check hidden key bytes/counts and subsequent INSERT/UPDATE/DELETE. Inventory and a demonstrated recovery path with failure/rollback tests are a release gate; do not claim deployed indexes are automatically fixed. If DROP and ADD are separate transactions, disclose that ADD failure can leave the index absent: base rows must remain intact, metadata must remain consistent, and the error must reach the operator. Respect deployment controls rather than silently dropping or rewriting customer indexes. Existing stopped-cluster fence, 4.2→main new-ENUM bridge hold and catalog/recovery gates continue independently.

## Required proof

- Typed/unit/negative tests in both branches: pure SET and mixed index statements mark exactly the permitted special-type AST references; UINT64, unrelated SET, user serial/expressions, nested/session reuse and internal statements without the option remain unchanged. Verify all in-process option construction call sites and explicitly test that no SQL syntax or automatic executor inheritance supplies the option; do not assert malicious Go callers are excluded. Verify legal quoted names, wrong account/source/target/domain/shape and actual schema drift fail closed, with cleanup after cancellation/retry. Preserve ENUM domain/encoding checks.
- Real SQL: compare inline-created index with rows-before-ADD for pure SET and both ENUM/SET key orders. Assert complete hidden key/payload byte sets and counts before/after INSERT, UPDATE, DELETE and reinsert, including the reproduced failures; compare actual selected-index versus scan results. Cover bitmap 0 and bitmap 1 with `SET('', 'a')`, NULL, multiple members and high-bit boundary, plus strict/IGNORE as supported. Assert both intended affected rows and data, not only no errors.
- Cover SET `serial_extract` plan domain propagation and physical 0/1, NULL, numeric and visible results through actual chosen index-only and scan plans, including a typed consumer; verify no additional bitmap loss relative to the same scan. Test `INSERT SELECT` separately: main must preserve 0/1/2/3/4/NULL through scan and index, while 4.2 must match its exact release baseline; do not misattribute the 4.2 pre-existing display-assignment behavior to index extraction. Include permitted SET-prefix controls against inline DML and exact hidden bytes; compare baselines and MySQL separately before compatibility claims. Confirm recognized SET UNIQUE/PK rejection, including main single-empty-member SET; verify 4.2 empty-payload UNIQUE/PK acceptance, and cover ordinary UINT64, VARCHAR and ENUM-only controls.
- Exercise temp tables and two simultaneously alive sessions, a non-system tenant, failure after partial work, cancellation/retry, restart and rebuild of an actually affected test index. Construct a competing old corrupt index, verify from the actual physical plan that rebuild reads authoritative base rows rather than that index, and inject failure across any separate DROP/ADD boundary. Verify source rows, catalog and hidden index on failure. Preserve protocol-floor and remote-plan checks. Run affected owner race/static and independent final review on exact committed content.

This is a proposed design only; the versioned design gate, implementation, migration policy and final validation remain open. No product worktree file was modified.
