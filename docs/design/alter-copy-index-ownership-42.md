# COPY ALTER index ownership on 4.2-dev

Base: `a7bc2008e9236708fee0328376f2c2c6b6f0d3fc`, after the complete revert of #32253 in #32483. Owner issue: #32056. This document replaces the earlier design drafts; the design-only commit preceded implementation. Design sessions used `gpt-6.1-terra` with `max` reasoning.

## Contract and responsibility

A replacement index has one backfill owner. Cloning requires proof that stored keys, included values, and row locators preserve their identity, values and physical encoding. Uniqueness and population are separate decisions: permission to omit deduplication never permits leaving an index empty.

The ALTER planner computes `SkipIndexesCopy` once, after all clauses, from the final schema and actual COPY projection. Both explicit and serialized INCLUDE metadata use the existing canonical parser; malformed or ambiguous metadata fails closed. Source proof checks the original column ID and sequence number, the surviving mapping, ordered primary-key membership, value-relevant types, and generated-value preservation. ID zero is valid. Type provenance (`Typ.Table`) is not physical encoding. Same-name DROP/ADD, changed composite-key members, reordered keys and recomputed generated keys invalidate the relevant proof. Implicit locator aliases use the complete locator proof, including hidden composite and fake keys.

Regular, unique and master indexes are populated by the COPY INSERT when affected and cloned when unchanged. Both INSERT builders suppress plugin maintenance for the qualified COPY target; the compiler invokes each plugin's clone or rebuild exactly once. The old clause-local impact accumulation and `AffectedCols` plan field are removed; protobuf tag 14 and its name are reserved.

Executor statement options carry one `InternalInsertOptions` with a qualified target and purpose. COPY admission and unique-index backfill share dedup options without sharing generated-column or auto-increment privileges. The executor restores statement context after nested execution. The replaced context keys and option getters are removed.

## Values, source validation and metadata

ADD, DROP, RENAME, CHANGE and MODIFY preserve the actual source lineage across the whole ALTER statement. Unchanged materialized generated values are copied; unproved values are recomputed. Recomputed incoming/self-referenced generated FK values are rejected before replacement. Schema-version validation and RC retry rebuild stale plans before accessing hidden relations. Removing one FK retains the parent's reference until the final FK to it is removed.

PK dedup may be omitted after a proof of unchanged complete key values or a source NULL/duplicate precheck on the locked COPY snapshot. The precheck additionally requires unambiguous source IDs, matching sequence numbers and the actual final mapping. FLOAT/DOUBLE decline this optimization because grouping equality is not the required physical identity proof. Target validation remains enabled when proof is absent. Legacy INSERT cannot use source unique-column shortcuts to bypass a changed target key or omit its hidden-table population.

Existing AUTO_INCREMENT zero values survive COPY independent of SQL mode; a newly added auto column still allocates values. The typed preinsert flag is propagated through construction, duplication and pipeline serialization. Matching ENUM/SET definitions preserve their stored ordinal/bitmap without a lossy display-string round trip.

Shared column-rename handling preserves implicit PK aliases, prefix lengths and nested session settings. FK-only catalog updates are gated at their producers, so index metadata updates also run for system tables. Visibility and parameter updates do not overwrite one another. COPY restores visibility and captured session settings only for surviving hidden-index identities. Internal identifiers and catalog literals use SQL quoting helpers.

## Asynchronous ownership

COPY creates rows in its transaction workspace. An inline build sees them, but the transaction snapshot predates their commit. Registering a tail from that snapshot replays the copied rows onto the built index. The compiler adapter therefore selects a post-commit complete snapshot only for the exact replacement relation: COPY scope, qualified name, resolved new table ID and a different original source ID. Nested REINDEX and unrelated operations keep their own scope.

Synchronous builds remain available for queries within ALTER's transaction. HNSW subsequently replaces its graph from the committed complete source snapshot. It starts from empty models, preserves the old generation floor, and replaces metadata/model rows and progress in one output transaction. Empty snapshots still delete output and publish progress. Tail consumption continues to load existing models. The second build is an explicit cost of preserving synchronous query behavior without inventing a transaction commit watermark.

SQL FULLTEXT/IVF snapshot retries reset derived output in bounded batches of 8192 rows before replay. IVF retains centroids and metadata while replacing entries. Every independently committed reset/write transaction validates the active job generation and source/hidden-table identities, and writes the same job row that retirement changes. Readers can still observe incomplete output while an asynchronous SQL snapshot is rebuilding; completion is published only after all guarded batches finish.

cuVS event sinks cannot recreate a trained ANN model from tail records. Their compiler plugins implement `SourceSnapshotInitializer`, returning the existing clear and full-source build statements. Clears use DELETE WHERE TRUE so the delete-to-truncate optimization cannot replace the guarded physical relations. Format-specific snapshot framing belongs to the cuVS writer. The job definition records `InitSQLCoversSnapshot` only for that explicit contract; nonempty SQL, algorithm name and `startFromNow` are not coverage proofs. The raw/statement-array InitSQL representation is unchanged. Existing jobs without the coverage fact remain conservative. Both affected and cloned COPY registrations use the same plugin owner; duplicate registration cannot silently retain an obsolete initializer.

InitSQL keeps its admitted Init status separate from tentative success: callback, watermark or commit failure cannot make retry skip initialization. InitSQL acquires the Running generation before work, validates source/output identity in its output transaction, and invokes completion in that transaction. A proved full-source initializer publishes its actual source snapshot with the model. A model-only/unknown initializer preserves the last safe cursor and still requires source snapshot consumption. A same-transaction self-retirement leaves its exact successor untouched. No new REINDEX routing or self-drain bypass is added.

FULLTEXT2 and cuVS retain monotonic tail chunk generations across replacement, including empty output, using valid zero-operation frames. Marker frames preserve INCLUDE headers where required and add no documents or maintenance operation counts. FULLTEXT2 compaction that emits no base (including live zero-term shadows) and empty REINDEX also retain the floor. Remote reuse compares the existing base timestamp and tail MIN/MAX. Both bounds come from one tail query: changed MIN or regressed MAX forces full reload; unchanged MIN and advancing MAX retains the append-only fast path. Failed capture does not install reusable state or mark a later observation as the loaded generation. No new persisted generation or frame encoding is introduced. Local caches are invalidated after output transaction completion; an eviction only inside Save can otherwise let a concurrent query reload the old committed model. Existing remote generation checks remain the freshness owner; no query-time progress polling is added.

## Failure, cancellation and recovery

The exact active key is `(account, source table ID, job name, job ID, LSN)` with an expected state. Admission changes Completed(n-1) to Running(n); output plus successful progress changes Running(n) to Completed(n). Failure publication can update only Running(n), preserving the last safe cursor. Inclusive change intervals retry from `From.Prev()`, or zero for a snapshot.

A failed acknowledgement is not proof of rollback. After releasing the writer, final publication reads the exact durable generation in a fresh transaction. Completed, terminal, newer and retired outcomes are preserved. This reconciliation acknowledges a terminal iteration; an errored/repaired completion at the old cursor does not prove successful output. It is retried under a new LSN by the scheduler. Group members are reconciled independently, so completed siblings are neither overwritten nor replayed. A same-LSN Running row alone does not establish runner ownership. Only a known admitted runner publishes failure; the worker-level failure writer is removed. Missing exact job IDs are pruned independently, while malformed metadata returns a diagnostic without writing sibling outcomes. Queued/admitted fencing and uncertain ownership abandon the executor generation asynchronously and return to existing task-lease expiry and startup recovery; a fence followed by DDL rollback therefore cannot silently strand a locally pending job. Consumer completion retains per-member fence observations through its cancellation cause and group result, so removing a fence before final publication cannot erase an observed stop; completed siblings keep their outcomes. Retry exhaustion cannot overwrite a completed generation with an older LSN.

Idle watermark writes preserve initialization stage and diagnostics, check their CAS result and change memory only after commit. Work and publication retain the caller's deadline. Existing bounded transaction cleanup retains submitted work until commit/rollback returns; confirmed outcomes are not erased by late cancellation. Typed work/commit errors retain their identity when cleanup/readback also fails. Cancellation after channel close terminates rather than spinning on a closed queue.

## Scope and evidence

Acceptance covers composite and generated PK changes, no-op cloning, raw secondary locators, both INSERT builders, prepared reuse, subsequent DML, conversion collisions and rollback, generated/FK races, ENUM/SET and AUTO_INCREMENT zero, prefix/alias/visibility metadata, system-table uniqueness, snapshot failure/retry, empty output and executor handoff. Owning packages run normal/race tests, vet and configured incremental analyzers; protobuf regeneration and SQL BVT are checked separately. The replacement PR records exact revisions and results.

Local GPU hardware is unavailable; CPU-runnable SQL-generation, framing and transaction-ownership controls are required locally, while native GPU runtime checks require GPU-capable CI. Native GPU algorithms and model formats are reused. This is a stopped upgrade from 4.2; concurrent old writers that perform unmarked empty tail resets cannot supply the new replacement-boundary invariant and are not a supported rolling-upgrade guarantee.

Two independently reproduced baseline defects remain outside this change: pending IVF initialization lost during an unrelated clone-eligible COPY, and partition COPY child-index loss. ALTER algorithm selection is unchanged. Existing global startup repair also retains its separate availability limitation when an unrelated transaction holds a job row; this PR does not claim to redesign executor startup.
