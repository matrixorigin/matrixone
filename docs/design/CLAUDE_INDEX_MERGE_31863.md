## 1. 问题、目标与非目标

当前 `applyIndicesForFiltersRegularIndex` 只选择一个普通索引；`checkIndexFilter` 的 OR 检查仅接受同一列。分别在 `k`、`v` 上建立索引后，`k = 3 OR v = 10` 仍无法使用两个索引的并集。

目标是在有收益且语义安全时，让各 OR 分支通过已有普通二级索引找到物理主键，合并去重后直接服务主键覆盖查询，或通过已有 INDEX join 回表。不能以“出现索引节点”替代真正降低扫描工作的证据。

非目标：新存储结构/执行算子、索引交集、任意 DNF 展开、主键扫描与二级索引的混合 union、新增索引编码能力、索引维护改造、分区表、存储过程、UDF、warning 兼容性。遇到这些形态保留既有访问路径，不改变结果。

## 2. 语义契约

设每条基础记录的物理主键为 `p`，谓词为 `A1 OR ... OR An`：

1. 真正满足任一分支的行不能遗漏。可用于回表的候选集合允许假阳性，但必须是结果行主键的超集。
2. 同一基础行同时满足多个分支时只返回一次；不同基础行即使投影值相同，也不能合并。
3. 只有分支条件在索引侧完整、精确地验证，且所有剩余表达式所需列都可用，才允许无回表路径。
4. NULL 遵循 SQL 三值逻辑：WHERE 只保留 TRUE。不能用 `NOT A` 作为 OR 第二分支的排重条件来误丢 `A IS NULL` 的行。
5. 去重、必要的残余过滤先于聚合与 LIMIT/OFFSET；不得把全局 LIMIT 推到单独分支。
6. 所有分支与基表使用同一事务/快照、同一归属表和权限上下文；遵守现有 USE/FORCE/IGNORE INDEX 约束。
7. 优化构造失败不能污染原始扫描、列映射、hint 或 LIMIT 状态；选择器检查失败回退原计划，真实 SQL/目录错误不伪装为成功。

最小反例：只命中右分支、同时命中两分支、左分支为 NULL 而右分支为 TRUE、不同主键但相同投影值、LIMIT 在去重前执行。

## 3. 先例与方案比较

参考 MySQL 8 的 [Index Merge Union](https://dev.mysql.com/doc/refman/8.0/en/index-merge-optimization.html)，仅借鉴多索引候选按行标识合并的方式，不要求复制其算子命名或代价参数。MO 普通索引已有隐藏索引表、物理主键映射及 INDEX join，应复用本仓库机制。

| 方案 | 优点 | 缺点/决定 |
|---|---|---|
| 维持全表扫描 | 实现最简单 | 保留本 issue 的性能缺口 |
| 改写成多个完整 SELECT 的 UNION | 可复用关系算子 | 整行去重可能破坏 bag semantics；分支重复回表，聚合/排序/NULL 处理复杂，不采用 |
| 二级索引主键并集、一次去重、可选一次回表 | 去重身份明确，复用现有结构，可直接服务 COUNT/主键查询 | 需要成本和残余语义证明，选用 |
| 新增存储层 bitmap/index-merge 算子 | 有进一步优化空间 | 扩展执行和生命周期边界，对当前问题过重，不采用 |

## 4. 候选发现与范围

第一版保留已有单索引访问优先级；仅当既有规则没有选出可用索引访问时尝试跨索引 OR。此取舍避免改变已经工作的覆盖索引、同列 OR、AND 以及排序访问规则；未来全候选统一竞价不是本次目标。

- 识别扫描 FilterList 中的 OR，递归拉平连续 OR，不分配 AND 的笛卡尔积。
- 最多处理 8 个 OR 叶分支；超过即保留原计划。预算限制分支规划及新增算子数，UT 覆盖 7/8/9 边界。
- 每个分支必须可由一个现有普通二级索引产生安全候选；至少使用两个不同索引，否则交给既有规则。
- 优先覆盖直接比较、IN、已有安全范围/复合前缀组合。分支内 AND 仅复用已有索引访问能力，不能据此扩大可索引表达式的语义范围。
- 复用索引有效性、列类型/字符序、浮点、前缀、生成列、runtime-constant 和参数比较安全检查；不放宽现有拒绝条件。
- 对会改变求值域的 volatile、可能抛错表达式或无法证明安全的条件拒绝新优化。类型转换等边界由既有安全判定和新的反例测试共同约束。
- 额外的顶层 AND 条件可保留为残余。若有多个可合并 OR，只选择成本最优的一个作为驱动，其余保留，不叠加指数级候选。
- 参数化查询只在能够证明安全并符合现有参数估算策略时使用新路径；估算未知不等于零成本。

## 5. 数据流和所有权

```text
索引扫描 I1 → 必要的索引侧 SQL 残余 → 投影物理 PK ─┐
索引扫描 I2 → 必要的索引侧 SQL 残余 → 投影物理 PK ─┼→ 主键 UNION DISTINCT
...                                             ─┘        │
                              ┌───────────────────────────┴────────────────────┐
                              │                                                │
                    精确 PK 覆盖路径                                  非覆盖/候选超集路径
                    重映射外部主键引用                                已有 INDEX join 回表
                    由原上层执行聚合等                                完整残余、原上层算子
```

使用现有 UNION 去重能力（编译为已有集合/聚合实现），不添加 protobuf node 或执行算子。

- 第一责任人是 `QueryBuilder` 的普通索引选择器；候选元数据仅活在单次规划中。
- 候选评估不修改原扫描。物化过程在隔离的节点/表达式和列映射中进行，成功后一次发布根节点和引用替换；失败不留下可达的半成品计划。
- 复用隐藏索引表的物理主键，包括复合主键编码、无显式主键表的隐藏主键。用户列值不是去重键。
- 原例 `COUNT(*)`：分支精确过滤后只需主键并集，不应再扫描基表；普通主键投影同理。未证明安全的主键解码/表达式覆盖走回表，不猜测。
- 回表保留完整原始谓词，在统一去重结果上生成已有 INDEX join 所需的主键连接与 runtime filter。不会为每条分支重复扫描基表。
- 各索引扫描继承 `ParentObjRef`、快照、hint 和上下文；引用替换及后续列裁剪必须通过真实 planner/compile 消费者验证。
- 不能把回表输出行数视作物理读行数。主键分散时可能仍触及许多块；成本不合算则拒绝该访问路径。

## 6. 成本、资源与退化保护

与现有普通索引代价模型使用同一工作量口径，包含：各索引实际预计读块/字节与过滤成本、传递 PK 的字节数、union/去重开销、需要时的基表块读取和残余求值。不能只累加最终命中行数，也不能假设各 OR 分支互斥。

- 去重输入按各分支候选行数之和计费；union 不同主键数至多为该和与表行数的较小值。
- 对回表复用 `regularIndexBackfillInputRows` 的块级保守估计与既有 PK 容量策略，不把最终 OR 选择率直接当作回表块选择率。
- 新路径仅在可比较估算下确有收益时自动采用。统计缺失、无效、过宽分支或预算超过既有能力时保留原计划；不复用“小表无条件忽略成本”作为新增多分支路径的默认准入。
- 缺失列 NDV、退化范围 min/max 或通用范围估算器的 `0.1` 失败回退值，不作为自动准入的可靠收益证据。真实范围选择率恰好为 10% 时也保守回退。
- 回表计入现有 `regularIndexBackfillPrepareWork` 的每 reader 键编码/描述符成本；非排序主键额外计入现有 IN 查找比较工作。保持和普通单索引回表的物理成本契约一致。
- FORCE INDEX 只按现有约定影响可选索引和成本偏好，不能绕过语义安全、分支数量或执行资源约束。
- 分支枚举时间受分支数上限约束；不在行级热路径增加 Go 分配、后台任务、全局状态或锁。
- 去重内存与实际不同 PK 数量及键宽相关，属于现有集合算子/查询内存管理，不把统计估计冒充硬上界。验证取消、内存错误、关闭的现有消费者路径；若发现依赖算子没有需要的资源约束，暂停并重新 review，不静默引入无界新机制。

## 7. 错误、生命周期、兼容性与运维

- 空集合、部分分支为空、重复命中使用普通集合语义；不新增重试或缓存状态。
- 执行错误、取消、超时由已有扫描/union/INDEX join 的错误传播和清理负责，不新增 goroutine 或跨查询资源。
- 无目录、索引维护、磁盘、wire 或公共配置变化，无数据迁移。重启继续使用现有数据，已有备份/恢复契约不变；不扩展混版本运行支持。
- 默认自动成本准入，不新增配置开关。IGNORE INDEX 可用于对照；回滚通过撤销 planner 规则完成，无存储回滚步骤。
- EXPLAIN 使用现有索引名、union/去重和 INDEX join 节点表达计划，不新增日志或高基数指标。
- 权限与租户隔离不能因为查询改扫隐藏索引表而绕过原表校验；继承既有索引访问的归属信息并做对应白盒检查。
- 不承诺所有 OR 都走索引；全表扫描在低选择率、统计未知或语义不支持时仍是正确回退。

## 8. 改动地图与验证

| 改动闭包 | 风险 | 预计位置 | 证据 |
|---|---|---|---|
| OR 候选合法性、预算、成本选择 | R3：规划与执行热路径 | `pkg/sql/plan/apply_indices.go`、聚焦的新 helper 文件 | fixture 驱动的安全/成本/边界 UT；保持既有索引测试通过 |
| PK 并集、覆盖消除回表、引用替换 | R2/R3：结果/执行资源 | planner 构造代码及现有 compile 消费者 | typed plan + 真实 SQL 独立结果 + 编译/执行证据 |
| 公共 SQL 回归 | R2 | `test/distributed/cases/optimizer/secondary_index_or_merge.sql` 及 result | mo-tester 生成、审查与比较；清理后重跑 |
| 大表收益 | R3 | worktree 内不提交的验证材料 | 原例/控制组 EXPLAIN ANALYZE、物理读/输入统计 |

现有 `secondary_index_range.sql/.result` 已覆盖单索引范围、NULL、复合/隐藏主键，但无跨索引 OR。选择独立小 case 是因为新契约需要两个索引、重叠/NULL 数据和独立成本控制，不向已有大文件继续追加无关 fixture。

UT 使用现有 planner fixture 注入统计，验证：

- 两索引与三个分支、同列 OR、AND 对照；存在未索引分支时不得漏行。
- 重叠、NULL、空结果、bag semantics、聚合、排序及 LIMIT/OFFSET。
- 单列/复合/隐藏主键；覆盖与非覆盖；索引 hints、快照与归属信息。
- equality/IN/支持范围的相邻控制；不安全比较、非稳定表达式和参数未知的回退。
- 高/低选择率、缺失/无效统计、宽 PK、输入容量与分支预算边界。
- 构造中途失败时原计划和映射不变；消费者能完成列裁剪、重映射、编译及执行。

BVT 使用少量确定性数据验证结果与 `IGNORE INDEX` 对照，性能门槛不放入普通 BVT。成本统计不足时，用公开 ANALYZE 或合法 hint 构造确定路径，并且独立的大表验证必须证明默认无 hint 的自动选择。

性能复现单独使用 `generate_series(1,200000)`：`id=result, k=MOD(result,500), v=result`。跨列 `k=3 OR v=10` 应为 401 行，同列 `k=3 OR k=7` 为 800 行。COUNT 验收要求默认计划确实由两个索引的去重并集驱动且不扫基表；报告索引实际读取工作，不能仅报告 401 输出行或查询耗时。

工具链取自 `go.mod`，当前为 Go 1.27.1；CGo 测试经 `mo-cgo-test`。修改包 focused UT、所属包测试、增量 vet/lint、改动覆盖率至少 75%，再做公共 SQL 和性能验证。多 CN 使用已有回归环境证明 union 及去重边界，不新增分布式协议；不涉及持久格式，因此无需升级/备份迁移专项。

## 9. Review 决策与停止条件

- 当前决定：**v1 已按批准范围实现并完成本地验收。**
- 已批准的取舍：保留已有单索引优先级；新增路径限 8 个 OR 分支；只复用已有安全二级索引能力；统计不可靠时回退；优先把原例的 COUNT/主键覆盖路径真正变为无基表扫描。
- 原实现最小回归已经验证失败；实现使用 UT、公开 SQL BVT 和独立规模验证闭合。本节所列目标不是无条件支持承诺，验证状态和运行记录单独保存，不纳入设计文档。
- 若实现必须新增执行节点/存储语义、改变索引维护、放宽比较安全、引入共享生命周期，或成本单位/主键去重语义无法闭合，停止并更新设计后重新 review。
- 后续 PR 必须链接已批准设计的准确版本；TODO 不提交。未获得额外授权不评论/关闭 issue，不自动发布 PR。
