# Resolver-owned borrowed reads for mixed temporal index costing

Issue: #32318. Implementation PR: #31944. Design revision: v2, 2026-11-06. Author: gpt-6.1-terra/max. Baseline inspected: clean `/mnt/nvme/pr31944-rebased` at `0ec56525a6687e2a9698ee9ba771fafb2ba98606`; merge base `65b721e1b93c6b9e05db2063b220e0c35916b335`. This is a design for independent review, not implementation or performance evidence. Reconcile the actual PR head and base before work starts.

## Decision

Replace ambient native relation capture with a typed result of the **same ordinary resolver operation**, explicitly supplied to the particular root optimizer attempt. The base result belongs to that builder's original scan ID; the winning hidden-index result is function-local. Drop the references when optimization returns. This removes the frontend temporal capture frame, the planner's relation registry and the frontend's retained scope lifecycle. Retain existing transaction/read visibility checks, pair verification, intent validation, range/residual semantics, selection policy and cache replan fact.

This reverses v1's conclusion that the existing frontend frame had to remain. I found no reachable supported same-compiler execution in which a lexical result would be attached to another builder or an unchanged transaction stamp would be used as a concurrency lock. Current frontend request handling is sequential: `server.go:878–927` calls `RoutineManager.Handler` before reading the next command, and `routine_manager.go:405` guards requests with `tryBeginRequest`. Synchronous internal metadata work in `GetSubscriptionMeta` uses a separate shared-transaction back-session and compiler (`compiler_context.go:1619,1844`), whose resolutions the existing per-`TxnCompilerContext` frame does not gate. Nested SET-derived SQL temporarily swaps and restores an `ExecCtx` in `util.go:274–290` and `back_exec.go:1034–1102`; it is a real reentry path, but its own explicit resolver result cannot be inserted into the outer builder. `SetExecCtx` itself (`compiler_context.go:151`) does not advance the current frame revision; therefore the existing frame is not a general ABA lock. The old frame detects attachment/reentry while its own capture is active; it does not serialize all users of a shared transaction. Transaction revisions and catalog visibility detect changes, but **are not a mutual-exclusion permit**.

The proposal depends on the existing single-request/statement ownership contract, not on concurrent mutation becoming safe. It must not authorize a new caller to run multiple goroutines against one mutable compiler/workspace. Direct injected reentry tests and the final `-race` closure must falsify that assumption; if a supported same-session concurrent workspace actor is found, stop and revise this design to use its existing serialization owner. Do not invent a replacement temporal frame or infer safety from a matching stamp.

## Scope and invariants

The optimization remains the currently supported, parameter-free, fixed-zone, simple, covering AUTO path. FORCE/LIMIT, prepared parameters, named zones, joins, non-covering access, and new comparison types are not admitted by this work. The existing result for an eligible query, its fallback on unavailable native data, diagnostic behavior, and the shuffled sparse benefit must remain. For every SQL predicate `P` and physical candidate `C`, `P(row) = TRUE` implies `C(row) = TRUE`; execute the full original SQL residual before any early stop. Preserve scale rounding, strictness, NULL, zero/sentinels, physical tails and time-zone behavior. `types.BuildTemporalCandidate` and the existing candidate/guard provenance remain authoritative.

| Responsibility | Owner after this change |
|---|---|
| Function stability, early evaluation, diagnostics and parameter provenance | Existing `function` and `rule` facilities plus the current positive `temporalCandidateBoundSafe` proof. Stability alone cannot admit SYSDATE, external/UDF effects, invalid `NOW(7)`, warnings or source-bearing materialized parameters. |
| Original/current predicate and physical range | Current original-owner proof, rewritten reader-shape proof, typed mixed temporal inversion and residual/guard code; these prove different phases. |
| Table, index, tenant and snapshot routing | Existing `TxnCompilerContext.resolve` and `ResolveIndexTableByRef` implementations. The richer result adds no second open. |
| Borrow lifetime | The current `QueryBuilder` holds at most 64 lazily allocated base scan records until its attempt returns; a winner holds one hidden result in a local variable. The engine/transaction owns the relation and cleanup. |
| Transaction and pair proof | Actual operator selected inside `getRelation`; `TryCatalogReadStamp`, workspace `CatalogVisibility`, and existing `disttae.TemporalIndexRelation` validation and `VerifyTemporalIndexPair`. Cost stats do not authorize rows. |
| SQL privileges | Existing post-plan `authenticateCanExecuteStatementAndPlan`; `makeRegularIndexOnlyScan` retains the logical base `ParentObjRef`. A resolved borrow is not a privilege grant. Preserve each retry's existing authentication boundary. |
| Cache and compile | Existing `TemporalIndexNeedsReplan` producer/consumers, prepared `valueDependent`, timezone/schema/protocol invalidation and compile placement/retry checks. They remain necessary as explained below. |
| Selection and cost | Existing ordinary regular-index candidate scorer/selector and BASE parallel-reader owner. Temporal code supplies bounded inputs, never a second selection policy or persistent statistics mutation. |

## Concrete API and data flow

Use two narrow, real operations, not a general observer or a second catalog implementation. Names below define the intended API; the definitions can live in `pkg/sql/plan` with `engine.TemporalRead` as today:

```go
// BorrowedTable is planner-only and valid only during this optimizer attempt.
// The resolver/transaction retains ownership. Owner is an opaque originating
// execution identity used only by the resolver to revalidate the borrow.
type BorrowedTable struct {
    Relation engine.Relation
    Full     *plan.TableDef
    Read     engine.TemporalRead
    Owner    any
}

type BorrowingTableResolver interface {
    IsSameCompiler(CompilerContext) bool
    ResolveBaseForPlanning(db, table string, snapshot *Snapshot) (*ObjectRef, *TableDef, *BorrowedTable, error)
    ResolveIndexForPlanning(base *ObjectRef, table string, snapshot *Snapshot) (*ObjectRef, *TableDef, *BorrowedTable, error)
    BorrowStillCurrent(CompilerContext, *process.Process, *BorrowedTable) bool
}

type TemporalPlanningInput struct {
    Root     *tree.Select
    Intent   TemporalPlanningIntent
    Resolver BorrowingTableResolver // nil unless frontend positively injects it
    claimed  atomic.Bool            // attempt-local; no Close or retained sources
}
```

`Owner` is the actual `*frontend.ExecCtx` used by the resolver, never serialized, exposed as authority, or retained beyond Optimize. If a type-safe private frontend token can avoid `any` without introducing a new owner/callback lifetime, use it; the semantics and lifetime above are mandatory. `IsSameCompiler` in `TxnCompilerContext` performs an **exact** `ctx.(*TxnCompilerContext)` assertion plus pointer identity. Frontend constructs the input by an exact assertion on the `CompilerContext` actually passed to the build; it never discovers a promoted optional method on a wrapper and never unwraps to an embedded compiler. If the compiler is a `viewSchemaCompiler`, `viewDependencyCaptureContext`, `viewDescriptionDependencyContext`, `viewSchemaCompilerContext`, compile delegate, mock, or other wrapper, set `Resolver=nil` and use its established `Resolve` methods unchanged. Preserve intent even when the resolver is nil, because it also affects original cache classification. `IsSameCompiler` is rechecked at the two use sites; a wrapper cannot acquire the borrow through Go method promotion.

Normal `Resolve`/`ResolveIndexTableByRef` remain because they have over 100 real non-temporal planner call sites, not as a temporary compatibility alias. Their existing public signatures remain. Both their descriptor-only calls and the two richer methods invoke one ordinary private implementation for the respective base/index policy. There is no duplicated name resolution or new catalog read. Refactor the six actual `getRelation` callers to pass a nil or optional read-observation output; nil does no stamp work. In `getRelation`, select the real txn, including any snapshot clone, **then** capture the pre-open stamp/visibility for an eligible request before `Database`/`Relation`. Do not guess the selected txn by reading the handler outside this function. On completion of the same normal descriptor path—including `GetTableDef`, legacy recovery, temp/subscription checks, and reference construction—recheck the same `ExecCtx`, process, handler operator, tenant/context, cancellation and all stamp fields/visibility. Snapshot overrides, temp/subscription/foreign domains, invalid/stale identity, lack of `TemporalIndexRelation`, or inability to obtain a nonblocking stable stamp yield a nil borrow with the same ordinary ref/def/error. A normal resolution error or cancellation follows the current error path. Both pre/post checks use the real operator; compare transaction ID, snapshot, revision, workspace and visibility. Keep existing `temporalNativeSnapshotOverride` logic in the resolver's private read helper.

The typed method is called only when input is claimed and the exact compiler matches. Otherwise call the compiler's ordinary method once. It must never call the ordinary resolver and then re-open a table by name, nor cause a second recovery, metadata walk, subscription, wait or I/O. `BorrowStillCurrent` checks the exact compiler, captured execution identity, process, current handler operator and live context; the existing `TemporalRead` and storage methods independently check txn/workspace/visibility. At every observer use and final publication, retain the existing intent/process and `context.Cause` checks. Same-context identity alone is not an ABA proof; snapshot and workspace revision changes, including change-and-restore, fail the storage/read check. A nested read that returns to the same valid owner/domain has no cross-builder capture to misassociate.

### Root claim and attempts

Change `BuildPlanWithTemporalScope` / `OptimizeWithTemporalScope` and the existing explicit frontend build helpers to accept `*TemporalPlanningInput`, passed only along the actual SELECT or `ParenSelect` and transparent EXPLAIN/ANALYZE/PHY wrapper. A SELECT claims it only if `Root == stmt` and `claimed.CompareAndSwap(false, true)` succeeds. All unrelated and nested `BuildPlan` entry points receive nil. The input is owned by the synchronous call; it is not a replacement compiler-context stack, has no mutex, no relation list, no callback, and is never placed in the plan or frontend cache. The atomic single claim preserves the current exactly-one-winner contract when callers race; it does not make concurrent compiler or workspace use safe. Verify `Intent.MatchesProcess` exactly as now. If a wrapper or other path could call the same attempt concurrently, it is outside this single-request contract and must not be admitted without a separately established owner.

For prepared execution, construct a fresh input from the **actual cloned/parsed root AST** and exact compiler for each `Optimize` invocation in `BuildPreparedExecutionPlanWithTemporalIntent`; the FIELD metadata rebind gets a new input and a new builder, not the first claimed input. `PrepareString` parsing must not claim an input for another AST. `rebuildPreparePlanWithTemporalScope` becomes the existing prepared rebuild returning only the plan; its fresh cloned `PrepareStmt` creates the input for its actual inner root. EXPLAIN uses its actual transparent inner root. Retry/safe rebuild uses the existing intent/placement policy and a fresh attempt; an unscoped safe rebuild remains candidate-free. Do not transfer the input or its borrowed values through `PreparedExecutionPlan`, `TxnComputationWrapper`, `Compile`, runtime cache or retry closure. Preserve the frontend's separate `temporalPlanningIntent`, `temporalIntentValidated`, `validateTemporalPlanBeforeCompile`, compile placement/clock/zone checks, and post-plan authorization and all existing prepared metadata publication/rollback rules.

### Base, hidden and atomic publication

At `query_builder.go:13891`, call the injected resolver for the actual base resolution. It returns the original full def before `CloneTableDefForPlan` at `:13923`. If this becomes a real ordinary `TABLE_SCAN` at `:14191`, record `(scanID, ref identity, full, relation, read, owner)` in a lazily allocated, bounded builder-local slice. Never associate a view descriptor with the scan produced by binding its view body; the body's actual scan records its own result. Index by exact scan ID and verify name/ID/version/full-vs-current scan again at use. Preserve duplicate table-ID and 64-record fail-closed behavior for actual scan bindings. No relation on a rejected, absent, canceled or non-table binding is retained. Clear the slice in a `defer` around the entire bind/optimize attempt, on success and every error/panic; clear every element before dropping its backing array. Original shape checks still gate optimization, and any change in current eligibility caused by eliminating incidental captured lookups must be identified in baseline-vs-candidate tests; do not broaden unsupported shapes under this refactor.

At `temporal_cbo_access.go:58`, locate the original scan's borrow directly, validate its owner and `read.Op == proc.GetTxnOperator()`, then use the existing copied cost stats, bounded scalar and block-observation paths. The ordinary selector still ranks candidates. Only the winner calls `ResolveIndexForPlanning` at the existing `:228` call, yielding a local hidden borrow from the same ordinary resolution. Check hidden/full reference identity and the same execution/txn/snapshot/workspace/visibility. `VerifyTemporalIndexPair` retains the current base full/pruned schema, hidden schema, index parent/key, tenant, revision, budget, stop and process checks. Construct hint, residual copies and mapping privately; revalidate both owner/domain and intent and cancellation immediately before `genNewBindTag`, map copy and `appendRegularIndexOnlyScan`. A nil/unsupported optional borrow falls back to unchanged BASE; a real resolver/cancellation/resource error follows its existing error owner. No partial tag, mapping, node, `ForceOneCN` or planner-visible result may escape failure.

- `query_builder.go`, `types.go`, `build.go`, `optimize.go`, `build_dcl.go`, `prepared_binding.go`, `temporal_cbo_access.go`: implement the explicit claim, scan-ID association, base/index borrow use and fresh-input rules above. - `frontend/compiler_context.go`, `mysql_cmd_executor.go`, `computation_wrapper.go`, `prepared_execution.go`: add exact-concrete injection and shared ordinary resolver result; remove `TxnComputationWrapper.temporalScope`, `replaceTemporalScope`, all scope close/transfer calls, `PreparedExecutionPlan.TemporalScope`, and `rebuildPreparePlanWithTemporalScope`/`MatchesQuery` lifecycle. `MatchesQuery`'s current frontend use only decides whether to transfer that retained scope; the native consumers are synchronous. Keep prepared reauthorization, AST ownership, metadata/rebuild rollback and safe fallback unchanged.
- Replace the removed scope/frame tests with focused direct-result ownership and reentry tests at the actual resolver/builder seams. Preserve distinct snapshot-ABA, nested planning, cancellation, duplicate, scope bound, cleanup, authorization and prepared execution oracles; delete tests asserting only implementation-specific frame depth/retirement. Do not preserve old and new routes in production.

This is a real ownership reduction: before, ordinary resolution indirectly publishes into a compiler frame, then a locked scope registry, then a name/ID/version search; frontend retains the scope past optimization and runs release/sweep. After, one resolver returns the result directly to the builder scan and to the one winning call; there is no retained frame or scope lifecycle. The private descriptor and richer methods share one resolver implementation. The estimated deletion includes 258 frontend and most of 191 planner scope lines and their scope-transfer code, offset by a smaller per-builder record, direct API and tests; exact net changed code, allocations, wrappers and test cost must be measured, not assumed. `TemporalPlanningInput` is transient root data and one atomic claim bit; it is not a new independently managed transaction owner. The 106 ordinary callers do not migrate.

## Deliberately retained boundaries and alternatives

**Cache:** `collectOriginalTemporalOwner` must continue setting `Query.TemporalIndexNeedsReplan` for a potentially eligible BASE as well as an INDEX. Dense first then a future sparse `NOW()` bound is the decisive counterexample: runtime freshness cannot recost a cached BASE. Conversely, suffix-only `(id,d)`, unsupported logical shapes and permanently ineligible statements must retain ordinary/prepared reuse. `Node.NotCacheable` is not an equivalent prepared rebuild policy, and marking only a winner misses BASE. Keep the current field and its existing frontend ordinary/prepared/generation consumers, `state.valueDependent`, and timezone invalidation. An eventual generic rebuild policy is separate unless it removes real equivalent existing decisions and passes the same reuse controls. This refactor does not rename the field, alter protobuf numbers or broaden globally stable-function rebinding.

**Typed candidates and effects:** keep the range/guard fields, runtime fold and compile/retry/reader provenance; removing or generalizing them requires all consumers to understand necessary-vs-exact candidates and preserve residuals. At UTC, DATETIME `.123499` can equal TIMESTAMP(3) `.123000` after SQL rounding, so a raw exact-point key excludes a true row. Keep `IsRuntimeConstant`, `GetFunctionValueUnstableByID`, bound FSP validation, `Literal.Src` provenance and positive total/effect-free admission at their existing strengths; a negative volatility flag is not proof of purity or safety. Keep bounded cached block observation: identical global min/max/NDV on ordered and shuffled layouts does not imply identical BASE work.

**Alternative A, retain the current scope:** safest fallback if the direct implementation fails its ownership tests or does not reduce overall complexity. No current correctness defect is asserted. **Alternative B, change the entire `CompilerContext.Resolve` signature:** exposes the richer result to all callers, but forces at least 106 non-test planner call-site changes plus wrappers/mocks; no additional independent consumer is established. Do not take this churn for this issue. **Alternative C, assert an optional richer interface on arbitrary compilers:** smaller superficially but Go embedding can promote a method past `viewSchemaCompilerContext.Resolve` and bypass its routing/recording. Reject in favor of exact frontend injection and `IsSameCompiler`. A second lookup after binding adds work and cannot prove it is the original relation; reject it.
