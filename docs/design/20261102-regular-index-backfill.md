# Regular-index backfill cost and exact IN probes

Issue: [matrixorigin/matrixone#32015](https://github.com/matrixorigin/matrixone/issues/32015). Implementation: the PR containing this document. Design-first owner: GPT-6.1 Terra/max; reviewed before implementation, with separate amendments for array ordering, prepared-bound uncertainty and physical locality. Base revision: `3474c0f743977460929241a1364137190f65135e`.

## Contract and observed work

A noncovering secondary-index join uses an exact primary-key IN filter to select base rows. The join forwards those rows rather than rechecking candidate membership, so neither false positives nor false negatives are acceptable. The IN values are normalized to sorted, non-NULL values before the reader uses them. Physical block rows, notably fake primary keys, need not be sorted.

On the measured warm 1M-row, two-CN workload, 1,000 matches on a table without an explicit PK spent 98.98% of CPU in the unsorted row-by-key loop. AUTO took 190 ms versus 1.52 ms for a scan. A real-PK equality with 100,000 matches read 124 blocks and took 50 ms versus 1.95 ms for a scan, while accurate statistics already estimated 100,000 rows. Constructing each reader's packed-key filter included an eager duplicate membership map. These measurements establish two separate costs; they do not justify a global selectivity cutoff. Some ordinary range backfills already choose a scan, while bare `COUNT(*)` can read metadata without scanning blocks.

For valid physical SQL PK domains, block search must return each matching offset once in input row order, regardless of duplicate needles or physical row order. SQL NULL needles, collations and unsupported representations continue to use existing normalization and safety guards. An internal float-array IN has numeric needle ordering but the legacy unsorted comparison is byte equality; SQL does not allow array primary keys. Preserve that unsorted internal behavior without claiming the pre-existing sorted array path is exact.

## Design

* Search each unsorted block row in the already normalized candidate vector by binary search, using the same equality and ordering domain as the existing predicate. Keep the old linear factory for small or unnormalized inputs. Fixed-size keys use their existing type comparators; byte-ordered varlen values use byte comparison. Float arrays keep their legacy exact byte-linear path because numeric and byte order differ. Fake PKs remain on the unsorted owned-vector path, not ObjectIO's varlen cached-search path. Do not retain borrowed block vectors beyond a callback. Normalized candidates are immutable for the reader lifetime.
* Keep the packed IN values sorted for committed replay and workspace range checks. Replace eager membership maps with pointer-owned lazy lookup holders on nonempty IN leaves. A holder uses sync.Once to construct and publish a complete immutable map when a workspace row first probes that leaf. SetFullData replaces the holder; concurrent reads share it, while mutation/reset require exclusive ownership. Keep binary search for empty or unavailable lookups. Allocate the encoder's result descriptors to their known final length once instead of repeatedly growing the slice. One private synchronous vector encoder lends packer bytes to workspace comparison without per-row copies; retained-key consumers clone those bytes. Packed payloads remain owned across packer reuse; fixed constants retain their repeated-value aliasing and variable constants retain independent payload ownership. CDC, ISCP, workspace and logtail consumers retain the same positional keys. Packing remains per-reader; changing its lifetime or sharing across readers needs a separate ownership design if subsequent measurements justify it.
* Keep the established relative index-candidate ranking and add a separate automatic backfill admission estimate. Per local reader, candidate preparation copies two slice descriptors and one encoded payload per key; estimate the local reader count from the existing DOP/block estimates, CPU and query DOP limits. Add an estimated one-reader encoding and allocation CPU cost once per key; real work may repeat across readers. These are estimates, not guaranteed latency bounds or global CN counts. Compare that preparation with the existing base-scan work, which accounts for its independently estimated input blocks. For sorted PKs, price optimistic K-row PK and payload reads without double-counting a projected PK: the statistics cannot establish whether those keys occupy adjacent or scattered blocks. The previous upper scattered-block estimate incorrectly rejected a measured clustered-key winner. For nonempty unordered PKs, estimate probing the surviving base input, including PK-column reads and logarithmic search CPU; zone maps may reduce the actual work. A zero-key filter has zero base probes. Apply the admission estimate to ordinary equality as well as other regular backfills, while preserving the established prefix-specific safeguards.
* A scattered-block estimate is an upper locality estimate. For rejection of a prepared candidate with unknown range bounds, preserve the existing optimistic lower-bound comparison: do not use speculative block expansion, full unsorted probing, sort work or reader multiplicity in that lower bound. A known set of adjacent keys may occupy one block when an unknown branch is empty.

The current selectivity/cardinality limits, small-table preference, covering access, direct PK point preference and FORCE bypass remain in place. Invalid or unavailable statistics retain the existing incomparable-score fallback. No SQL-specific or fake-PK-only cutoff is introduced. Relative candidate ranking remains a heuristic and can miss differences in preparation or scattered locality; neither it nor admission is a correctness assumption.

For N block rows and K candidates, supported fixed-size and byte-ordered searches use O(N log(K+1)) comparisons, with O(N) for constant-size K. The float-array legacy path remains O(NK). The existing candidate vectors and packed keys remain bounded by runtime-filter/query limits. An initialized workspace IN leaf retains an additional O(K plus encoded key bytes) map; readers without workspace probes retain only its small holder. Reader/disjunct fan-out multiplies this memory, which is Go heap state rather than transaction workspace index accounting. Construction under the existing transaction lock is not interruptible; measure this latency alongside probe throughput. selector and scratch space is bounded by block rows, including existing disjunction scratch. The existing reader owns merged-vector cleanup and filter lifetime; no new goroutine, shared cache, wire, catalog or persisted format is introduced. Constructor failures and close/reset use the existing source/filter cleanup paths. An exact bounded-memory path remains available without substituting a Bloom filter.

## Alternatives and validation

Lazy exact hash lookup trades bounded-by-input retained memory for expected O(N+K) workspace work; pure binary lookup remains the fallback. It does not provide a universal memory ceiling or recover from fatal allocation failure. Sharing filters across readers would require new ownership and partial-construction protocols. Reducing the global selectivity threshold would miss differences in width, locality and parallelism and would leave forced backfill slow. Enabling fake-PK cached search or using Bloom alone is unsafe because neither proves exact membership for these rows.

Focused reader tests compare unsorted results to an independent linear oracle, including boundaries, duplicates, null normalization, float zero and array numeric-vs-byte-order controls. Encoder, CDC, ISCP, workspace and replay tests exercise retained packed keys, packer reuse and existing cleanup. Planner tests cover broad equality, selective and covering controls, FORCE, small tables, DOP and missing statistics, plus prepared unknown bounds whose known adjacent keys may fit in one block. Public SQL tests compare forced index and scan results across persisted data and transaction mutations. No unit or SQL regression uses timing as its correctness oracle.

The prior warm 2-CN baseline is reused; the corrected binary is measured against the same no-PK 1k/2k/5k forced cases, broad real-PK AUTO/scan case, and selective/covering controls with matching results and actual plan shapes. The quadratic hotspot must disappear. Final validation includes owning packages and directly affected reader/planner consumers in normal and race modes, affected incremental static checks, and an independent final review of the exact change.
