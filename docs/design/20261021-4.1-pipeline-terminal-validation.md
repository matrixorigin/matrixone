backport and local validation. Every changed hunk was reviewed with its owners

| Closure | Ownership (Q1) | Waits (Q2) | Growth (Q3) |

existing pipeline deferred spool cleanup. Correctness, lifecycle, liveness,

## Additional white-box regression, 2026-10-21

`pkg/vm/pipeline/terminal_delivery_test.go` adds two cross-package scenarios,
each for Connector and two-receiver broadcast Dispatch. It uses real sender
Call, Pipeline.Cleanup and Merge.Call, with the existing MockOperator supplying
input. There are no production hooks or new production changes.

| Test | Forced state | Required result |
| --- | --- | --- |
| TestPipelineCleanupDeliversEndAfterBackpressure | two one-row batches occupy both spool slots and all notification capacity; consumer starts only after producer cleanup | both values arrive in order, End is observed without cancellation, final outstanding off-heap bytes are zero |
| TestPipelineCleanupPreservesSpoolAllocationFailure | one published row fills notification queues; copying a second 2 MiB row exceeds a private 1 MiB mpool cap | cleanup aborts pending work; every receiver gets the exact allocation error, and outstanding off-heap bytes return to zero |

The full-queue precondition is asserted directly. A scoped short legacy terminal
send timeout bounds the old implementation's cleanup; it does not schedule or
trigger the state. A separate consumer context ensures producer cancellation
cannot make a missing terminal look successful. The consumer deadline is an
outer hang guard and successful assertions require that it has not fired.
Tests are serialized; timeouts, contexts, batches, pools and operator ownership
are cleaned up locally, including early assertion failure.

The exact same test file was copied to an isolated stock v4.1.6 worktree at
`3c7eb8de7f2388de84624fdaf719cc218f8078dc`. It uses only APIs present in that
release, so the negative run compiles and reaches all four scenarios. Production
source in that worktree is untouched. Native libraries were copied from the
already-built identical release inputs after proving no changes in `cgo`,
`thirdparties`, `go.mod` or `go.sum`; `make thirdparties` was run in both trees.

* Stock 4.1.6: exit 1; all four subtests fail. Both normal paths read the queued
  values and then hit the independent consumer deadline because End was lost.
  Both allocation-failure paths return queued data instead of the required abort
  error. Log: `whitebox-baseline-red.jsonl`.
* Fixed source: owning pipeline package normal PASS (0.039s), race PASS (1.162s).
  Logs: `whitebox-owning-normal.jsonl`, `whitebox-owning-race.jsonl`.
* Each exact new test independently repeated 100 times under race: PASS, 200
  top-level passes / 400 sender subcases. Counts use the measured durations and
  the existing adaptive 30-second rule. `whitebox-stress-summary.json` records
  exact selections, commands and counts.
* Focused pipeline vet: exit 0; release-configured lint: zero new issues.

Test/review scope is the new pipeline fixture and this record. The existing
design remains applicable; this focused test-only addition is exempt from a
new feature design. Q1: pending/current batches retain their established owners
and the memory oracle closes allocation and final release. Q2: full capacities
are forced before cleanup; the receiver must terminate independently of producer
cancellation. Q3: at most two published rows, two receivers and one deliberately
rejected row; no service, socket, background worker or unbounded retry is added.
Self-review: PASS, no unresolved blocker. The earlier service/mo-dump/prepared
and other-package evidence is reused because production inputs are unchanged.
This models allocation failure, not an OS OOM kill.
