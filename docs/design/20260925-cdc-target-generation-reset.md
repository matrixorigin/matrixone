# CDC generation-safe target admission for PR #28521

Status: proposed rev4, awaiting product/design approval. Date: 2026-09-25. Owner: PR #28521. Rev3 was approved; rev4 closes a newly discovered EndTs lag case and corrects the default split-mode description.

## Problem and scope

At PR head `326eec3f3ed4224e19debc8c5a90bb801aeaee1c`, the detector shares one `IdChanged` marker across CDC tasks. A successful task can acknowledge it, another task can fail, and the first task can receive the same marker on resume. Its sink executes `DROP TABLE IF EXISTS` and resumes from an advanced watermark, losing rows. A deterministic reproduction registers A and B to the same source, lets A acknowledge a source replacement while B fails, then unregisters and re-registers A: A receives `[true,true]` rather than `[true,false]`. A fresh CN can also miss the scanner's process-local transition. Finally, an old reader may advance its watermark beyond the replacement source table's first writes; resetting the target and replaying from that old timestamp also loses rows.

This revision assumes, per the product scope decision, that simultaneous old/new CN binaries and downgrade compatibility are outside this PR's acceptance. Same-version CN takeover, restart, source replacement, retry, and legacy task data safety remain in scope. The design does not close issue #26949's cross-table replication lag or enable CDC on a source without a user primary key.

## Smallest durable state

Reuse the existing per-task/table `mo_cdc_watermark` row and existing source-generation-keyed snapshot epoch row. No new catalog column, task code, MORPC version, ledger, worker, or periodic scan is required. For generation-aware tasks, `source_table_id=g` now means **target initialization for `g` has been durably acknowledged**; subsequent checkpoints continue to carry the same `g`. `watermark` is the replay position for that generation, except that an initial NoFull/start task retains its durable admission boundary after initialization. The target lock serializes target effects; `owner_generation` fences all catalog writes. The scanner's `IdChanged` remains a scheduling hint, never authority for DROP.

New tasks persist a generation-aware option in existing task metadata. **All generation-aware task creation paths require the existing v48 catalog/protocol capability** (`owner_generation` and `mo_cdc_snapshot`) before persisting the task, including atomic full, explicit StartTs, and NoFull. No new MORPC version is needed under the same-version rollout scope. Existing fenced stable tasks with `source_table_id>0` may be admitted using their recorded generation after validation. **Every unmarked task with `source_table_id=0` is ambiguous**, even with an empty watermark: an old full sink transaction or partial split snapshot may have reached the target before its checkpoint persisted. Pause it unless durable epoch/target evidence proves a safe recovery. A new marked NoFull task can also have `(source_table_id=0, watermark=admission)` before its first target DDL, so row existence/watermark alone must not classify legacy state. The existing default full task uses split snapshots (the persisted boolean is false with the stable-epoch marker, and the runner restores split); an explicit `InitSnapshotSplitTxn=false` uses an atomic snapshot. Preserve that selected grouping in both modes and cap either first snapshot at the persisted epoch `E`. The current reader caps to `E` only in split mode and must be extended for atomic mode.

## Invariants and transition order

1. For a current claimant and source generation `g`, if durable initialized generation equals `g`, do not DROP due to a repeated detector marker. Verify that the CDC-owned target exists and has the expected structure; fail closed if it was externally removed or altered. External target row mutation is unsupported.
2. On first admission of a marked task, persist a fixed epoch `E` first if the task needs an initial full snapshot, including the explicitly selected atomic full mode. Initialize the target under its target lock, then synchronously acknowledge `source_table_id=g` under the current owner fence **before** publishing a reader. Preserve the NoFull/explicit-start admission timestamp. A crash before acknowledgement may repeat initialization, but no reader for that generation was published; a crash after acknowledgement preserves the target and reuses the original epoch. A first full snapshot never selects a new epoch after `(g,0)` is durable, whether the selected mode is split or atomic.
3. On a proven replacement `g>storedGeneration`, stop/drain the old local reader and updater, claim the watermark row, and **delete all epochs below `g` before creating** the fixed epoch `E` for `g`. Failure to clean up blocks admission. Old epochs are no longer needed after the old reader is drained and the source has advanced to `g`; the generation-bounded SQL cannot delete `g` or newer. Under the target lock, reset/create the target once; while still holding the lock, atomically set `(source_table_id=g, watermark=0)` under the owner fence. Only then release and publish the new reader. A crash before this catalog transition may repeat DROP using the same `E`; after it, retry preserves the partial target and the same `E`. A stale old-generation checkpoint cannot overwrite `g`.
4. The recovery reader ignores the old-generation watermark. A replacement table created after the task's admission may be fully replayed over `(0,E]` for NoFull and ordinary full mode; every row in it is post-admission. For **any** explicit user StartTs, replay the replacement relation's changes over `(StartTs,E]`, preserving the user filter whether the relation was created before or after StartTs. If complete historical changes over that range cannot be read, fail closed. If the current snapshot is earlier than StartTs, do not reset or publish a reader yet; wait/retry until a snapshot at or after StartTs is available, and choose `E>=StartTs`. If EndTs is earlier than StartTs, complete according to the existing empty-range contract. The recovery mode is explicit and independent of the original `noFull` or snapshot-split setting. It then tails from `E`, including the `StartTs=E` empty-replay case. Checkpoint order is `(generation, timestamp)`, so `E` may be less than the old watermark. The reader/cache must load the new `(g,0)` after the admission transition, not reuse the old cached timestamp.
5. The epoch for `g` is immutable until the final initial/recovery snapshot checkpoint commits. A partial snapshot retains both epoch and target. If `(g, watermark<E)` lacks its original epoch, fail closed; do not invent a later epoch over partial target rows. Snapshot retention/stale reads also fail closed. The final checkpoint commits only after the complete replay and target writes. Generation-bounded cleanup with owner checks occurs **before inserting `E`**, and is repeated before reader publication if needed after an uncertain result; a cleanup failure blocks admission and is retried. Thus repeated source replacements plus failed target DDL cannot accumulate epoch rows. The current `g` epoch remains until completion, then can be deleted. At steady state and during normal admission, at most one epoch row per task/table is retained after cleanup.
6. An uncertain target DDL, catalog write, lock release, cancellation, or owner change never counts as admission. Resolve uncertain catalog outcomes by a fenced reread. A target reset and catalog acknowledgement are ordered effects across two systems, not an atomic distributed transaction. Same-version CN takeover must use the same owner-fenced row and target lock.

The current stable restart classifier, updater cache, sink initialization, and `table_change_stream` NoFull/snapshot guards need to implement these transitions. In particular, current incomplete-epoch logic must not DROP again after `(g,0)` is durable, and the old `!noFull && startTs.IsEmpty()` condition must not disable replacement replay. Snapshot epoch capping is independent of transaction splitting: both selected modes use durable `E`; retry cannot choose a later snapshot. The target DDL and catalog acknowledgement must use the same target lock; the lock cannot be released at `CREATE` as it is today. `CREATE TABLE IF NOT EXISTS` must not hide a missing target when `g` is already acknowledged.

For finite EndTs, establish whether `g` existed at `E=min(current snapshot, EndTs)` with a historical read before resetting the target. If absent, leave the target untouched and complete only when the **durable, owner-claimed old-generation checkpoint `W>=EndTs`** and the prior CDC-owned target still exists with the expected structure. If `W<EndTs`, old-generation work remains unreplicated and the task stops with an operator recovery diagnostic; loss of the old source's history cannot be repaired by declaring the new generation complete. If the historical read or target validation is stale or unavailable, fail closed. Current catalog presence and `mo_tables.created_time` are insufficient proof. A future explicit StartTs waits for a snapshot `E>=StartTs` without consuming the error retry budget; the detector's ordinary rescan triggers another admission attempt after restart or while waiting.

## Legacy recovery and rollout

At upgrade, pause ambiguous old tasks before activating this admission rule, drain old executors, and classify their persisted watermark generation and task protocol. A fenced checkpoint with `source_table_id=g` and a valid target establishes that sink initialization preceded that checkpoint and can continue. A known older generation enters the replacement recovery path. A zero generation, including an empty watermark, cannot prove which source generation populated the target; it remains non-running unless other durable evidence proves a safe complete image. Before any `GetOrAddCommitted` or legacy NoFull fallback may write a synthetic admission timestamp, check the old task's durable row read-only; a missing row is also ambiguous. The runtime can use its existing `Failed` terminal state with a specific operator-recovery error to stop execution, while the operator-facing runbook calls this a safety pause. It must not silently resume. The operator may (a) prove a consistent existing target from retained source/target history, (b) explicitly rebuild the current source as a full image, accepting different NoFull semantics and cost, or (c) create a fresh NoFull task and clean target at a new admission boundary. Current row count or timestamp alone is not proof. Migration records the chosen action and establishes the new task option/generation before resume. An old NoFull target subset cannot be reconstructed after its needed history expires.

No mixed-version support is claimed here. While old and new CNs coexist, old-code tasks can still run under old semantics; this rollout requires those tasks paused and old CN executors drained before resuming under the new rule. A downgrade would require pausing generation-aware tasks and restoring their previous operating contract. Existing catalog backups include the reused watermark and epoch rows; task DROP/orphan cleanup must remove both.

## Cost, alternatives, and verification

The extra catalog acknowledgement is once per table admission/generation, never per CDC row or detector tick. Persisted storage remains one watermark row and at most the existing bounded epoch state per table. Clone only the subscriber account's detector map during fan-out rather than all tenants; before-change review benchmark allocated 18.3 MB/scan at 100 tenants × 10 tables and 72.7 MB/scan at 200 × 10. Keep independent descriptor copies and remeasure allocation. Persist a concrete task error for runtime keyless tables rather than pointing only to a potentially absent watermark error row.

| Alternative | Decision |
| --- | --- |
| Global `IdChanged` acknowledgement | Reproduced repeat DROP; reject. |
| Per-task in-memory acknowledgement only | Small same-CN hotfix, but loses source-change proof on process/CN restart; insufficient for systemic claim. |
| Add `target_initialized_source_id`, executor code, and migration column | Separates target and checkpoint meanings cleanly but adds catalog and mixed-version machinery without a needed same-version invariant; reserve if implementation proves existing-row acknowledgement unsound. |
| Reuse fenced watermark generation and fixed epoch | Chosen for same-version recovery. It may repeat DROP after a crash before acknowledgement, but no reader for `g` can have published and replay is complete. Data safety, not physical exactly-once DDL, is the invariant. |

Validation must include: A/B subscriber failure then A pause/resume without second DROP after `(g,progress)`; old watermark `W>E` with new-generation rows before `W`; first marked NoFull admission; first default split full and explicitly atomic full with crash before/after partial or atomic target commit and same-epoch retry; explicit StartTs before/after source recreation, `StartTs=E`, future StartTs with restart while waiting beyond the ordinary retry limit, and EndTs before StartTs; v48 task creation gate for every new mode; crash before/after each DDL and `(g,0)` commit; partial replay and same-epoch retry; repeated replacements with target DDL failures and bounded epoch rows; missing epoch; missing target; stale old checkpoint; EndTs historical presence/absence combined with old durable `W<EndTs` and `W>=EndTs`; old ambiguous task non-running recovery without manufacturing a watermark; independent CN process takeover; cancellation; normal/race CDC/frontend suites and real sink integration. Assert final target rows and durable state, not only internal marker bits. Run focused SCA/vet and before/after allocation benchmark. CI pending is not verification.

## Product decision

An old NoFull task with zero generation and nonempty progress is paused until explicit recovery. This is the recommended fail-closed policy. Approval of this exact design revision is required before production implementation under the MatrixOne `mo-dev` design gate.
