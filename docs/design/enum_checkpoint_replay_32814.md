# ENUM checkpoint replay and ALTER transfer validation

Issue: matrixorigin/matrixone#32814. Implementation: matrixorigin/matrixone#32824 (4.2-dev). This document supplements the existing ENUM identity and index-mutation designs; it does not approve the implementation on its own. The 4.2-dev catalog and RPC version constraints in those designs still apply.

## Problem and contract

An ALTER COPY that reauthors an unchanged, ordered ENUM member domain under a different identity must preserve the physical member ordinal, including 0 and NULL, for the corresponding old and new column. Ordinary INSERT and genuinely different domains retain assignment semantics. A checkpoint restore must not publish a script that silently substitutes an ENUM domain, table default, or view parser context for one in the checkpoint.

On the 4.2.8-upgraded catalog, legacy `ENUM('A','a')` ordinals 1 and 2 collapsed during a same-domain ALTER to general_ci. A numeric domain `ENUM('2','x')` exported ordinal 2 as `2`, which LOAD interpreted as member 1. A view created with `NO_BACKSLASH_ESCAPES` returned bytes `615c62`; globally disabling that mode during restore changed them to `6108`. Independently, missing `attr_enum` cells or an aligned NULL can be mistaken for the valid empty member. These are data/meaning changes, not formatting differences.

## Ownership, alternatives, and invariants

The ALTER compiler owns a statement-local proof: exact generated COPY SQL, account, source/target relation generations, resolved schemas and source-to-target columns. The INSERT planner may use physical ENUM transfer only for a direct, proven source and the same byte-exact ordered member domain. The optimized executable plan must trace the target write slot through the *physical semantics* of each admitted operator to the correct base-table column and actual ENUM cast. It rejects unprovable shapes before writes. The binding is removed from nested statements and reconstructed for replan. Generated source columns may transfer only after proving they are physically materialized and the target is an ordinary column; generated targets use their expression. Cross-version RPC remains gated by the existing ENUM protocol floor.

The preflight groups canonical ordered member domains once and records their identities, rather than decoding every old/new column pair. Legacy and framed encodings of the same domain compare equal; collation and original encoding remain part of the identity transition. This is O(total decoded domain bytes + number of columns), with storage bounded by distinct input domain bytes; malformed domains do not become valid matches. A different or ambiguous source sequence still reaches the scoped proof and must not silently take the physical path.

For checkpoint metadata, retaining raw strings alone is insufficient: a non-NULL empty ENUM member and an absent/NULL cell have the same textual representation. A sentinel string could collide with legitimate data; re-reading every catalog object would add I/O and could lose row association. Instead, the checkpoint reader retains compact per-row NULL/physical-absence bits while materializing the `mo_columns` and `mo_tables` catalog views. Row grouping must carry those bits with the exact row. A named or seqnum-mapped catalog uses that mapping; an exact historical positional layout is usable only when the relevant column position is unambiguous. An absent, short, NULL, unverified, malformed or ambiguous ENUM member cell fails before restore.sql is published; a known non-NULL empty cell remains a valid empty legacy domain. `extra_info` may be absent only in a proven historical pre-extra layout; missing or NULL in a layout that contains it fails closed.

An ENUM column DEFAULT is part of the stored schema, including later INSERTs that omit the column. Its persisted `plan.Default` must come from a known, non-NULL catalog cell; a missing or malformed expression cannot silently become `DEFAULT NULL`. No expression and an explicit NULL are different cases. Stored `OriginString` is already SQL-escaped, so the renderer must never escape its interior a second time. A bounded admission check accepts only a single canonical SQL literal (optionally parenthesized) with no trailing syntax, and rebinds it against the type that the emitted ENUM declaration actually constructs. That type is computed from the decoded ordered members and their target encoding and collation, not copied blindly from the old expression. Rebinding and the stored typed expression must compare exactly, or another explicitly proven equivalence must hold; otherwise script publication fails. This conservative rule may reject otherwise valid legacy defaults when reconstruction changes domain encoding, for example a singleton empty member. A column with a proven absent expression emits no DEFAULT; it must not acquire DEFAULT NULL, especially on a NOT NULL column. These checks apply to DDL-only as well as load-script restore.

The optional `--load-script` serializes ENUM values as decimal ordinals, while LOAD resolves matching labels first. A schema-level bounded check therefore refuses a potentially ambiguous ordinal/domain pair before publishing restore.sql; it may conservatively reject a table even if its current rows happen not to contain that ordinal. Raw CSV export and DDL-only `--no-load` remain available. This avoids per-row remapping and avoids publishing a script with silently wrong values.

Reconstructed DDL and LOAD delimiters use ordinary backslash escapes. Rather than impose the invoking session's mode on every recovered object, the script uses a dedicated session, saves its original mode, temporarily removes `NO_BACKSLASH_ESCAPES` for reconstructed DDL/LOAD, and restores the original at successful completion. Before each view it obtains the verified persisted `mo_tables.viewdef` creation SQL, parser SQL mode, default database, and security type, validates one CREATE VIEW and safely qualifies its target, then restores that context just for view creation. It subsequently restores the ordinary replay mode, security setting and current database. Invalid, missing, unsupported or unverifiable context fails before publishing the script. A nil persisted mode uses the engine's legacy `PIPES_AS_CONCAT` parser default. No implicit external database is created: a referenced default database outside the dump must already exist. View definer-role identity/privilege restoration is an existing limitation of this checkpoint script and is not claimed by this change; deployments needing exact definer-role recreation require a separately designed role-mapping restore.

The alternatives were leaving the entire script in the invoking mode (reconstructed escaped literals can be wrong), forcing one global mode (stored view SQL can change meaning), or guessing the mode from SQL (ambiguous syntax). Per-view persisted context is needed to reproduce both paths. Unrepresentable modes must be rejected, not silently normalized. `ANSI` is subject to the existing 4.2 SQL-mode SET conversion behavior and is accepted only if its target round trip is proven; otherwise it is explicitly rejected.

## Failure, resource, compatibility and validation

For `--load-script`, prepare the full selected restore set and preflight every newly introduced ENUM schema/default, numeric LOAD and view-context check before opening any CSV output. Batch and account dumps must apply the same system-table filtering as script generation, validate every selected table before starting any writer, and use the same prepared schema, snapshot and foreign-key ordering as the final script. A single-table dump uses the same checks. DDL-only mode skips only the numeric LOAD check. The final script path rechecks these conditions. A validation failure therefore leaves any previous script and CSVs untouched, even when the failing table follows another table in a batch. Existing partial-output behavior on I/O failure, interruption, external-source copying or concurrent use of one output directory is not made atomic by this scoped change; users needing a consistent output set must use a fresh dedicated output directory and must not rely on a prior script after such failures.

Script construction and all schema/view checks finish in memory before `restore.sql` is created. A failure leaves no newly published script; CSV already exported for a failed load-script request may remain as data artifacts and must not be treated as a valid restore. A dedicated client session confines a mode change if an error interrupts script execution before restoration. ALTER validation returns an error before the COPY writes if the relation, path, operator slot, cast or metadata cannot be proved; existing transaction ownership/cancellation/rollback remains unchanged.

Null provenance is tracked only for the two catalog views. Per row it costs one bit per catalog data column plus the slice header, and is included in the materialization byte budget where a limit is requested; the existing unlimited catalog path remains proportional to catalog rows and columns. Preflight grouping is linear in catalog rows and does not scan the catalog once per table. No new workers, network services, queues, external I/O, privileges or persistent format are introduced. The script still requires a restore identity authorized for the target databases, views and roles; it does not grant privileges or restore a definer's role.

Required evidence: (1) legacy/new identities and framed/legacy domains, reordered/different domains, NULL, empty/0, generated sources, column rename/reuse and unmarked INSERT; (2) optimized/replanned direct source-to-write paths including sink, pre-insert and dedup, wrong-child/wrong-slot and constant counterexamples, FULLTEXT and real remote COPY; (3) snapshot/branch, concurrent source update and rollback; (4) real 4.2.8 catalog checkpoint/restart and raw/collated ENUM replay, numeric-label rejection and DDL-only control; replay DEFAULTs authored in normal and NO_BACKSLASH_ESCAPES modes, including quote, backslash, numeric, empty, explicit NULL and no-default, then compare omitted-column INSERT value and physical ordinal; reject missing, invalid, stale or noncanonical typed defaults before script publication; (5) absent named/positional field, short row, true NULL, missing aligned object column, batch row validity, and known non-NULL empty member; (6) views under saved NO_BACKSLASH_ESCAPES, ANSI_QUOTES and PIPES_AS_CONCAT, differing modes/default databases/security types and subsequent normal DDL/LOAD, invalid metadata, mode restoration and no-load; (7) an existing S1 script and CSV set remain byte-identical when an S2 numeric, default/schema or view preflight fails in a single or multi-table dump, including account filtering and DDL-only controls; (8) affected owner race, incremental static analysis, and independent overall review. Evidence must distinguish 4.2 from main; main remains a separate implementation and mixed-version migration constraint.
