# Retire transaction data trace — revision 3

Owner: engineering-quality issue #29249; implementation: a separate retirement PR, linked on delivery. Base: 529ee099e32. Revision 3 incorporates the user's final clarification: an end-to-end runtime cut, with inert configuration and catalog declarations where needed for whole-cluster stopped-version replacement and rollback. No mixed deployment is supported.

## Evidence and ownership

CN construction captures an absent trace service before bootstrap registers it. Dynamic data/action probes remain, so traces are incomplete. Every CN still allocates four million-slot event queues and seven tasks. Enabled row-data serialization, blocking channel sends, CSV writes and retrying uploads/imports couple diagnosis to business latency and availability. Trace also leaves flags, session variables, DSN options, executor options, sequence/timing work and bootstrap definitions across owners. Standard spans, statement statistics, Explain/analyzers and reader summaries have independent consumers. Commit/rollback/closed callbacks also serve auto-increment, shard and ISCP correctness and must survive.

## Approved direction and acceptance invariants

Delete the complete transaction debug-trace runtime and all producers/consumers: CN construction/registration/close and directory ownership, transaction-open callback wiring, probes and their exclusively derived work, workers/queues/filters/loaders/formatters. Retain trace TOML fields and the session setting disable_txn_trace solely as inert configuration declarations; no consumer reads these values. Remove trace defaults, Go options, internal connection DSN parameters, executor enable/disable switches, protobuf option helper bit and runtime key. Remove command registration and handler rather than keeping a no-op or retirement alias. No GetService or dummy service remains.

Retain exact trace catalog definitions and bootstrap/upgrade registration so directory/schema contracts stay stable for stopped-version rollback, including fresh cluster initialization. Reduce the trace package to catalog SQL declarations only. Delete the trace export-directory declaration/creation/ownership code, causes, obsolete operational docs and exclusive tests. Existing stored databases/tables/rows and local/object-store files are never dropped, truncated, deleted, rewritten or replayed. A fresh cluster retains the same mo_debug schema, with initially disabled controls; those controls are never consumed by the new version. Existing historical data remains available through ordinary SQL and backup/restore, without a special reader or new schema migration. Existing service TOML files remain parseable in both versions; new-version parsing may retain old values without applying them. Dynamic CN positional templates are versioned launch assets and switch with the commit, including rollback. The generator removes the trace-only directory slot together with its templates; externally maintained older six-slot templates must also be replaced during the stopped switch. No template compatibility shim or reserved trace argument remains. Explicitly stopped replacement means no mixed-version protocol/fallback is required; rollback uses the prior commit. Other catalog/journal/recovery paths remain intact.

Remove the data-trace late-materialization fallback, keeping the independent reader-summary eager path. Preserve business clock measurements, metrics, transaction state transitions, crash recovery, retry/cancellation, lock/snapshot semantics, real commit/rollback/closed callback consumers and ordinary spans. Trace-only sequence/action callbacks and their tests are removed after consumer closure; event identities still used by correctness consumers retain their meaning. Existing unrelated on-disk/wire flag values are not renumbered merely to fill a deleted bit.

There is no replacement collector, cache, queue, worker, dual-read/write, compatibility execution branch or adapter. Retained inert configuration and catalog definitions are explicit data/config contracts, not dummy runtime APIs. After retirement the trace resource budget is zero allocations, service lookups, per-row serialization, polling SQL, trace file/network I/O and trace-only timestamp/sequence work. Performance percentages require measurement; structural deletion proves the removed work, not an end-to-end throughput number.

## Alternatives and failure closure

Repairing the collector retains an expensive parallel control/storage plane without demonstrated production consumers. A bounded sampled replacement is a new feature with its own admission, state and capacity obligations, outside the user's direction. An inert runtime facade keeps obsolete contracts and hot-path work; inert declarations alone admit old configuration without those costs. Complete deletion is the smallest enduring responsibility model. No interoperability standard requires this internal collector; retained ordinary SQL, transaction, journal and actual callback consumers define the boundaries.

Start/failed bootstrap/close use existing CN owners without a trace generation or cleanup participant. Existing CSV/object files are inert historical artifacts, never automatically removed. Real callback errors, canceled SQL, transaction retry and commit/rollback closure remain with their current owners. Security exposure is reduced by eliminating row capture and operational trace controls; ordinary SQL authorization continues to govern historical data. The lost capability is future row-level forensic capture, explicitly accepted by the user.

## Final removal gate

The retained declarations are temporary, tracked by #29249 and source TODOs. After several releases, remove them once the supported stopped-version rollback window excludes every collector-bearing version, deployed service TOMLs omit `Txn.Trace`, and client/session initialization no longer sends `disable_txn_trace`. Remove catalog declarations, bootstrap/upgrade registrations, trace-specific planner protection and declaration-only tests together. Removing source declarations does not authorize dropping historical tables, rows or files; any eventual data deletion requires an explicit retention decision. No runtime reader or compatibility service may be added during this window.
